### 1. Document model and canonical text

#### 1.1 Data model (`star/documents/model.py`)

`WordPos` (`model.py:8-16`) links one spoken word to its place on screen:

| Field | Type | Meaning |
|---|---|---|
| `word` | str | Token text. The comment says "stripped of punctuation"; in practice it is the regex match. |
| `tts_offset` | int | Code-point offset into `plain_text` |
| `tts_len` | int | Token length |
| `disp_line` | int | Rendered display line. In the TUI it is a line index. The Qt GUI keeps a separate char map, `_qt_word_map`. |
| `disp_col` | int | Column within that display line |

`Document` (`model.py:19-30`) holds one loaded document:

| Field | Type | Meaning |
|---|---|---|
| `path` | str | |
| `title` | str | |
| `markdown` | str | Display source |
| `plain_text` | str | Canonical TTS text |
| `word_map` | `List[WordPos]` | Filled in later by the UI, not by the loader |
| `metadata` | `Dict[str, str]` | |
| `format` | str | e.g. `"text"`, `"markdown"`, `"html"` |
| `encoding` | str | Default `"utf-8"`; never set by any loader |
| `chapters` | `List[(title, href, word_idx)]` | EPUB only. `word_idx` is always `0`; see §3.8. |

- `_WORD_TOKEN_RE = re.compile(r"\b\w[\w'-]*")` (`model.py:36`). This is **the** word tokenizer, shared by the TUI word map and the Qt word map (`star/gui/mixin_document.py:21`, where `_QT_TOKEN_RE = _WORD_TOKEN_RE`).
- `_align_word_offsets(spoken, rendered)` (`model.py:39-101`) lines up the spoken token stream with the display token stream using `difflib.SequenceMatcher(autojunk=False)`. It runs in chunks of 2000 tokens with 500 tokens of padding (`:76-77`). When the two lists are identical it takes the identity fast path (`:73-74`).
- `_build_word_map(plain_text, rendered_lines)` (`model.py:104-173`):
  1. It tokenizes `plain_text` and lowercases both streams.
  2. It aligns them.
  3. It fills gaps. A spoken word with no display match takes the offset of the **next** aligned word, a trailing one takes the **previous** offset, and if nothing aligns it uses 0 (`:143-155`).
  4. It converts each offset to (line, col) with `bisect` (`:158-161`).
  5. The result is monotone in `disp_line`.

#### 1.2 How `plain_text` is built

`load_document(path, settings)` (`star/documents/dispatch.py:107-342`) runs these steps:

1. **Archive refs and archives.** `path!member` refs and plain archive files are handled first (`:109-140`). For an archive, the member index Markdown is also used as `plain_text` (`:136-137`).
2. **Format detection.** `_detect_format` (`:77-87`) uses the extension map in `_EXT_FORMAT_MAP` (`:19-74`). An `http(s)/ftp` path is `"url"`. Unknown extensions become `"text"`.
3. **Document cache.** If `document_cache` is on (the default is True, `settings.py:120`), Star reads the cached `{markdown, plain_text, title, format, metadata}` keyed by a settings fingerprint (`:147-160`). It writes the cache only when `len(plain_text) > 1024` (`:321-340`).
4. **Pandoc first.** This happens when `prefer_pandoc` is on (True by default, `settings.py:293`), Pandoc is available (`pypandoc` or a `pandoc` binary, `pandoc.py:30-32`), and the format is one of `docx, odt, pptx, html, csv, tsv, xlsx, rst, latex, mediawiki, textile, creole, orgmode, notebook` or a Pandoc-only extension (`pandoc.py:11-14, 35-37`). Star then runs `pandoc --to markdown <path>` (`pandoc.py:56-64`). **Markdown, text and EPUB are never routed through Pandoc.**
5. **Plugin `FormatHandler`.** `PluginRegistry.get().handler_for(path)` (`:189-193`). The built-in handlers live in `star/documents/handlers.py:42-270`. Each one calls `_document_from_markdown` (`handlers.py:16-39`), which does the same tail work as step 7.
6. **Native loader branches** (`dispatch.py:199-279`). For the formats textweaver cares about:
   - `.txt` → `_load_plain_text`: UTF-8 read with `errors="replace"`, **returned verbatim as "Markdown"** (`text_loaders.py:7-11`). A `.txt` file therefore goes through the Markdown stripper, and a `#` at the start of a line becomes a heading.
   - `.md/.markdown/.mdown` → `_load_markdown` = `_load_plain_text` (`text_loaders.py:14-15`). **Front matter is not stripped.** Only `.rmd` strips it (`text_loaders.py:33`).
   - `.html/.htm/.xhtml` → `_load_html` → `_HTML2MD` (`html.py:266-274`).
7. **Tail** (`dispatch.py:293-309`):
   - **Title.** The first `^#\s+(.+)$` match, else the file name (`:295-297`).
   - **Footnotes.** Processed only if `footnote_mode != "inline"` (`:300-302`).
   - **Plain text.** `doc.plain_text = _strip_markdown_for_tts(md, skip_code=settings["tts_skip_code"], table_mode=settings["table_reading_mode"])` (`:305-309`). Defaults: `tts_skip_code=True` (`settings.py:64`) and `table_reading_mode="structured"` (`settings.py:285`).

#### 1.3 `_strip_markdown_for_tts` (`star/ttstext/markdown.py:11-80`): the canonical text shape

The steps run in this order. Every regex is quoted verbatim.

| Step | Line | Regex / action |
|---|---|---|
| Unordered list markers | `:29` | `re.sub(r"^\s*[-*+]\s+", "", text, flags=re.MULTILINE)` |
| Ordered list markers | `:30` | `re.sub(r"^\s*\d+[.)]\s+", "", text, flags=re.MULTILINE)` |
| Fenced code (skip_code) | `:34-35` | ```` re.sub(r"```[\s\S]*?```", "", text) ````, `re.sub(r"~~~[\s\S]*?~~~", "", text)` |
| Indented code (skip_code) | `:36` | `re.sub(r"^    .+$", "", text, flags=re.MULTILINE)` |
| Fences kept (no skip) | `:38-39` | ```` re.sub(r"```\w*\n?", "", text) ````, ```` re.sub(r"```", "", text) ```` |
| Headings | `:42` | `re.sub(r"^#{1,6}\s+", "", text, flags=re.MULTILINE)` (the text is kept) |
| Horizontal rules | `:45` | `re.sub(r"^(\*{3,}\|-{3,}\|_{3,})\s*$", "", …, re.M)` |
| **Images → alt text** | `:48` | `re.sub(r"!\[([^\]]*)\]\([^\)]*\)", r"\1", text)` |
| **Links → link text** | `:49` | `re.sub(r"\[([^\]]*)\]\([^\)]*\)", r"\1", text)` (the URL is dropped) |
| Inline code | `:52` | ``re.sub(r"`+(.+?)`+", r"\1", text)`` |
| Bold/italic | `:55-60` | `\*{3}(.+?)\*{3}`, `_{3}(.+?)_{3}`, `\*{2}(.+?)\*{2}`, `_{2}(.+?)_{2}`, `\*([^*\n]+?)\*`, `_([^_\n]+?)_` |
| Blockquote markers | `:64` | `re.sub(r"^(?:>\s?)+", "", text, flags=re.MULTILINE)` |
| Tables | `:69` | `_tables_to_narration(text, mode=table_mode)` |
| Collapse blank lines | `:72` | `re.sub(r"\n{3,}", "\n\n", text)` |
| **Join soft breaks** | `:78` | `re.sub(r"(?<!\n)\n(?!\n)", " ", text)` |
| Trim | `:80` | `text.strip()` |

What the result looks like **(verified: `sample.md.json`, `sample.txt.json`)**:

- **Paragraph separator.** Exactly `"\n\n"`. No other newlines survive: every single `\n` becomes a space (`:78`).
- **Headings.** The heading text becomes its own paragraph, with no terminal punctuation added. `Sample Markdown Document\n\n…`
- **List items.** The markers are removed, **and the items are joined with spaces into one paragraph.** They are not one per line, because of the soft-break join. `"First bullet item Second bullet item with emphasis Nested bullet under the second Third bullet item Step one of the procedure. …"`
- **Bug: headings merge into the following list.** `^\s*` in `:29-30` crosses newlines under `re.M`, so the blank line before a list is eaten, and the heading "Lists" merges into the list paragraph: `"Lists First bullet item …"` **(verified)**. The unordered and ordered lists merge the same way.
- **Tables** (`star/ttstext/tables.py:7-101`, `mode="structured"`). A table block is a run of lines that contain `|` **and** start with `|` after stripping (`:33-42`). Separator rows are dropped (`:64-65`: `all(re.match(r"^[-:]+$", c) for c in cells if c)`). Output lines:
  - `Table with N column(s): H1, H2, H3.` (`:82-84`)
  - `Row i: H1 is v1, H2 is v2.` (`:85-93`)
  - a blank line (`:99`)

  Then the soft-break join (`markdown.py:78`) **merges every row into one paragraph** with spaces: `"Table with 3 columns: Name, Role, Score. Row 1: Name is Ada, Role is Engineer, Score is 98. Row 2: …"` **(verified)**. In **plain_text** tables are therefore **not** one row per line. The cell separator is `", "` and the key/value joiner is `" is "`. One row per line exists only on screen (TUI §3.9, GUI HTML table).

  | Mode | Output |
  |---|---|
  | `"flat"` | each row becomes `".  ".join(cells) + "."` (`:72-78`) |
  | `"skip"` | `Table with N column(s) — skipped.` (`:44-53`) |
- **Images.** The alt text becomes plain words. An image with empty alt produces nothing. `A diagram of the reading pipeline` **(verified)**. On screen the TUI draws `[img: alt]` (`star/render.py:71-72`).
- **Code blocks.** Removed entirely (default `skip_code`), including indented code. Blank lines collapse around them.
- **Links.** Only the link text is kept.
- **Footnotes.** With the default `footnote_mode="inline"` (`settings.py:118`), **nothing is done**: `dispatch.py:301` skips `_process_footnotes` because "inline is already the default behavior", but no code implements it. `[^1]` stays in the text, and `[^1]: definition` is spoken as its own paragraph **(verified)**. `_process_footnotes` (`star/documents/misc.py:57-106`) handles the non-default modes:
  - `inline` would produce ` (footnote: …)`.
  - `deferred` appends `## Footnotes` followed by `N. text`.
  - `skip` removes the markers.
  - The definition regex is `^\[\^([^\]]+)\]:\s*(.+)$` (`:77`), and the reference regex is `\[\^([^\]]+)\]` (`:82,90,93`).
- **YAML front matter in `.md`.** It is not stripped. The `---` lines are removed as horizontal rules, and `title: … author: …` is spoken as the first paragraph **(verified)**.

#### 1.4 HTML loader `_HTML2MD` (`star/documents/html.py`)

**Skip list** (`html.py:8-26`): `script, style, nav, footer, aside, noscript, svg, canvas, meta, link, base, iframe, template, button, form`. A start tag increments `_skip` (`:53-55`) and an end tag decrements it (`:130-132`). Data is dropped while `_skip > 0` (`:202`).

> **BUG, critical (verified).** `meta`, `link` and `base` are void elements with no end tag. After an unclosed `<meta charset="utf-8">`, `_skip` stays at 1 forever, so **the whole document converts to an empty string**. That is what happened to `sample.html` with `prefer_pandoc=False` (`variants.native_prefer_pandoc_false`). XHTML's `<meta …/>` works, because `HTMLParser.handle_startendtag` calls start then end. So EPUB, which is XHTML, is usually fine.

Tag handling:

| Tag | Behaviour |
|---|---|
| `pre` | Emits ```` ```lang ```` using the `language-`/`lang-` class prefix (`:58-70`), raw data lines (`:205-207`), and a closing ```` ``` ```` (`:135-138`) |
| `h1`–`h6` | `"#"*n + " " + text` then a blank line (`:71-73, 139-144`) |
| `title` | Becomes `# title` at the **top** of the document (`:251-254`). The page `<title>` plus the `<h1>` produce the **heading twice** (verified in the diagnostic variant). |
| `p, div, section, article, main, header` | Flush on the start tag; paragraph plus blank line on the end tag (`:76-77, 157-158`) |
| `b/strong` | `**…**` (`:212-213`) |
| `i/em` | `*…*` (`:214-215`) |
| Both bold and italic | `***…***` (`:210-211`) |
| `code` outside `pre` | `` `…` `` (`:208-209`) |
| `a` | `[text](href)`, or plain text when there is no href or text (`:84-87, 165-169`) |
| **`img`** | `![ALT](src)`. ALT comes from `alt`, then `title`, then `aria-label`, then `""`, stripped. With `longdesc`, ` (long description: URL)` is appended (`:88-98`). An empty alt gives `![](src)`, which is spoken as nothing. |
| `figure` / `figcaption` | The caption becomes `*caption*` then a blank line (`:99-103, 146-156`) |
| `br` | A literal `"\n"` in the buffer (`:104-105`). The soft-break join later turns it into a space. |
| `hr` | `---` (`:106-108`) |
| `ul/ol/li` | `pad*"  " + "* " / "n. "` (`:109-116, 170-186`). **Bug:** a nested `<ul>` inside `<li>` flushes the parent item's text **without a bullet** (verified: `* Apples\nOranges\n  * Blood oranges`). |
| `blockquote` | `> ` prefix per nesting level (`:117-119, 187-189, 231-236`) |
| `table/tr/th/td` | Pipe table. The first row is the header; rows are padded to the widest row (`:238-249`). **Bug:** `<caption>` text lands in `_buf` and is thrown away at the first `</th>`/`</td>` (`:194` `self._buf = []`). |
| Whitespace | Collapsed with `\s+` → space, and `&nbsp;` → space (`:204`). Text that is only whitespace is ignored (`:202`). |
| Output | Runs of blank lines collapse and the result is stripped (`:255-263`) |

`HTMLParser(convert_charrefs=True)` (`:29`) decodes entities.

#### 1.5 HTML via Pandoc (the default when Pandoc is installed)

This route produced **(verified, Pandoc 3.9.0.2)** the problems below. They are not visible in the native path.

- A `\$` escape leaks into `plain_text`.
- `<table>` becomes a Pandoc *simple table*. It fails the `|` test, so it is spoken verbatim, dashes included: `"Name Score ------- ------- Ada 98 …"`.
- The table caption becomes `: Scores`.
- `<pre>` becomes 4-space indented code. It is dropped from speech, but the TUI shows it as a normal paragraph.

**Encoding bug.** `subprocess.run(..., text=True)` has no `encoding=` argument (`pandoc.py:58-62`, `star/markup/pandoc.py:22-27`), so on Windows Pandoc's UTF-8 output is decoded with the ANSI code page. Non-ASCII HTML and DOCX text is corrupted.

#### 1.6 Markdown handling summary

Markdown is read verbatim and never parsed as CommonMark. Three independent regex renderers exist, and they disagree:

| Consumer | Location |
|---|---|
| Speech | `_strip_markdown_for_tts` (§1.3) |
| TUI display | `star/render.py:127-295` |
| Qt display | `star/gui/mixin_document.py:969-1098` `_md_body_to_html` |

The Qt renderer emits **one `<p>` per source line** (`:1091-1093`), so it does not reflow paragraphs. It emits every pipe table as an HTML `<table>` (`:1006-1049`), with the first body column as `<th scope="row">`.

Other formats (office, ebook, `star/markup/*`) all reduce to Markdown and then go through the same stripper:

- **EPUB.** The spine's XHTML files go through `_load_html_str`, joined with `---` separators (`star/documents/ebook.py:80-110`).
- **Lightweight markups.** Each has a three-tier fallback: Pandoc, then a Python library, then a built-in regex converter (`star/markup/pandoc.py:1-10`, `text_loaders.py:97-227`).

### 2. Word and sentence segmentation

#### 2.1 Words

- **Tokenizer.** `_WORD_TOKEN_RE = re.compile(r"\b\w[\w'-]*")` (`star/documents/model.py:36`). It uses Unicode `\w`, so `café` and `crème` are single words.
- **Behaviour (verified, `sample.txt.json`):**

  | Input | Tokens |
  |---|---|
  | `O'Brien's`, `well-known`, `12-14`, `3rd` | one token each |
  | `e.g.` | `e`, `g` |
  | `2.0.1` | `2`, `0`, `1` |
  | `reader@example.org` | `reader`, `example`, `org` |
  | `$12.50` | `12`, `50` |
  | `€4` | `4` |

- **A trailing `-` or `'` belongs to the token.** The regex allows them at the end, so `rock-` is one token.
- **Offsets** are Python code-point indices.

#### 2.2 Sentences

The splitter is at `star/_runtime.py:721-725`, verbatim:

```python
_SENTENCE_SPLIT_RE = re.compile(
    r"(?<=[.!?\u2026])\s+(?=[A-Z\"\u201c\u2018(])"
    r"|(?<=[.!?\u2026])\s*\n"
    r"|\n{2,}"
)
```

- The comment at `_runtime.py:716-720` says: *"Intentionally simple — some abbreviations (Dr., Mr.) will cause false splits, which is acceptable."*
- **There is no abbreviation list for sentence splitting.** The only abbreviation list, `_ABBREV_PAIRS`, is used for speech expansion (§2.4).
- **Consequence (verified).** `Dr.` and `Mr.` become one-word "sentences". For example, `sample.txt` has sentences `"Dr."` and `"Smith opened …"`.
- **Opening characters.** A sentence can start with ASCII uppercase `A-Z`, `"`, `“`, `‘` or `(`. `É`, digits and `'` do not start a sentence.

**Sentence map** (TUI `star/tui/mixin_document.py:138-171`; the GUI copy is `star/gui/mixin_document.py:308-326`, and `star/gui/mixin_navigation/_editing.py:517-531` copies it again after an edit):

```text
char_starts = [0] + [m.end() for m in _SENTENCE_SPLIT_RE.finditer(plain_text)]
for each cs: advance wi while wm[wi].tts_offset < cs; append min(wi, len(wm)-1)
dedupe preserving order; empty → [0]
```

**Lookup:** `_find_sentence_idx(word_idx)` is a binary search for the last start `<= word_idx` (`tui/mixin_document.py:173-185`; GUI `_core.py:48-60`).

#### 2.3 Paragraphs

Star has **no plain-text paragraph segmenter**. A paragraph means different things in different places:

- **`plain_text`:** separated by `"\n\n"` (`markdown.py:72,78`). The splitter also counts `\n{2,}` as a sentence boundary.
- **TUI:** a run of non-empty rendered lines between empty lines. `rendered[i] == []` means blank (`tui/mixin_navigation.py:98-109, 218-244`). Heading blocks (heading line plus underline), list blocks, table blocks and code boxes are each one "paragraph".
- **GUI:** a run of `QTextBlock`s with non-empty `text().strip()` (`gui/mixin_navigation/_core.py:175-222`). Because of one `<p>` per source line (§1.6), block boundaries do not match Markdown paragraphs. See bug B11.
- **Reading level:** the Flesch-Kincaid feature uses a different split, `re.split(r"[.!?]+", text)` (`tui/mixin_document.py:232`).

#### 2.4 Speak-time normalization (`star/ttstext/pipeline.py:9-38`)

The order is fixed. Each step has its own setting:

1. Pronunciation lexicon: `use_pronunciations`, `pronunciations` (`:23-26`)
2. Abbreviations: `expand_abbreviations`, `abbrev_expansions` (`:28-30`)
3. Numbers: `normalize_numbers` (`:32-33`)
4. Math: `normalize_math` (`:35-36`)

**Abbreviation list, verbatim** (`star/ttstext/abbreviations.py:9-71`, applied in this order):

| Group | Abbreviation → expansion |
|---|---|
| Multi-word Latin | `et al.`→and others, `op. cit.`→op cit |
| Single-token Latin / English | `e.g.,`→for example,; `e.g.`→for example; `i.e.,`→that is,; `i.e.`→that is; `etc.`→et cetera; `cf.`→compare; `ibid.`→ibid; `n.d.`→no date; `ca.`→circa; `vs.`→versus; `approx.`→approximately |
| Academic / publishing | `Fig.`, `Figs.`, `Eq.`, `Eqs.`, `Sec.`, `Chap.`, `Ref.`, `Refs.`, `Vol.`, `vol.`, `No.`→Number, `no.`→number, `pp.`→pages, `p.`→page, `ed.`→edition, `eds.`→editors, `Dept.`, `dept.`, `Assoc.`, `Univ.`, `univ.` |
| Titles / honorifics | `Dr.`→Doctor, `Mr.`→Mister, `Mrs.`→Missus, `Prof.`, `Jr.`, `Sr.`, `Rev.`, `Gen.`, `Gov.` |
| Units / measurement | `hr.`→hour, `min.`→minutes, `sec.`→seconds, `wt.`, `avg.`, `temp.`, `conc.`, `est.`, `max.` |
| Business | `Inc.`, `Corp.`, `Ltd.` |

- **Matching.** Each pattern is `re.compile(r"\b" + re.escape(abbr))`, with no trailing boundary (`:76-79`). Custom entries are applied first, longest first (`:88-90`).
- **Missing entries.** `St.`, `a.m.`, `p.m.`, `Ms.` and `Mt.` are not in the list.

Numbers (`star/ttstext/numbers.py:171-290`) are handled in this order:

| Pattern | Regex | Line |
|---|---|---|
| ISO date | `\b(\d{4})-(0[1-9]\|1[0-2])-(0[1-9]\|[12]\d\|3[01])\b` | `:191` |
| US date | `\b(0?[1-9]\|1[0-2])/(0?[1-9]\|[12]\d\|3[01])/(\d{4})\b` | `:198-200` |
| Time | `\b([01]?\d\|2[0-3]):([0-5]\d)(?::\d\d)?\s*([AaPp][Mm])?` | `:223-225` |
| Currency | `([$\u00a3\u20ac])(\d[\d,]*)\.?(\d{2})?` | `:248` |
| Percent | `\b(\d+(?:\.\d+)?)%` | `:258` |
| Ordinals | `\b(\d+)(?:st\|nd\|rd\|th)\b` (case-insensitive) | `:261-266` |
| Comma integers | `\b\d{1,3}(?:,\d{3})+\b` | `:269-273` |
| Decimals | `(?<![\d/\-])\b(\d+)\.(\d+)\b(?![-/\d])` | `:279` |
| Integers of 4+ digits | `(?<!\.)\b(\d{4,})\b(?!\.)` (1000–2099 are read as years) | `:288` |

Integers under 1000 are left for the TTS engine.

**Math** (`star/ttstext/mathspeech.py:8-130`): it strips `$…$` and `\(…\)`, speaks `\frac`, `\sqrt`, `^`, `_`, Greek letters, trig functions and operators, then deletes every leftover `\\[a-zA-Z]+` (`:127`).

**Verified normalization defects** (in `normalized` of the parity JSON):

| Input | Output | Cause |
|---|---|---|
| `9:30 a.m.` | `nine thirty AMa.m.` | The time regex's `\s*` eats the space when no `am/pm` follows (`numbers.py:224`) |
| `3:30 p.m.` | `three thirty AMpagem.` | `p.` → "page" runs **before** the time rule, and 3:30 with no marker is AM |
| `for €4.` | `four euros` | The currency `\.?(\d{2})?` eats the sentence-final period (`:248`) |
| `20 min.` | `20 minutes` | The expansion swallows the period |
| `version 2.0.1` | `two point zero.1` | |
| `[^1]` | `[ to the 1]` | The math `\^(\w)` rule (`mathspeech.py:36`) |
| Pandoc `\$3.99` | `dollars and ninety-nine cents` | "three" is lost: `\three` is deleted as a LaTeX command (`mathspeech.py:127`) |

Also: `no.`/`No.` expand anywhere a word ends with them ("I said no." → "number"). `3rd St.` → `third St.`.

### 3. Navigation

**Terms.** "Current word" is `_current_word_for_nav()`.

- **TUI** (`tui/mixin_document.py:187-223`) tries, in order:
  1. the TTS callback word (`last_cb_word_idx`) while speaking
  2. the timer estimate while speaking
  3. the saved pause word `_tts_paused_at_word`
  4. the caret word `_caret_word`
  5. the first word with `disp_line >= scroll`
- **GUI** (`gui/mixin_navigation/_core.py:18-46`) tries:
  1. the callback word
  2. the timer estimate
  3. the first word whose Qt char offset is `>=` the text cursor position
  4. otherwise the last word

  **The GUI ignores `_tts_paused_at_word`**, but the pause moves the cursor, so this is usually equivalent.

#### 3.1 Sentence next / previous / replay

- **Next.** `nsi = si + 1`. If there is none: "No next sentence", and it **does not wrap**. It jumps to the first word of that sentence. Speech restarts only if it was speaking. Code: TUI `tui/mixin_navigation.py:37-53`, GUI `_core.py:122-139`.
- **Previous** (TUI `tui/mixin_navigation.py:55-72`, verbatim `if cur - self._sentence_starts[si] > 3: psi = si else: psi = max(0, si - 1)` at `:62-65`; GUI `_core.py:148`; Speech Cursor `tui/mixin_speechcursor.py:191`):
  - **The rule is confirmed.** If the current word index is **more than 3 words past** the sentence's first word (`cur - start >= 4`), previous jumps to the **start of the current sentence**. Otherwise it jumps to the previous sentence start.
  - At sentence 0 it stays at 0. It does not wrap.
  - Help text: `tui/text.py:434-435`.
- **Replay.** Jumps to the current sentence's start and **always** starts speech (`always_play=True`). TUI `:74-96`, GUI `_core.py:158-171`.
- **Status message.** It previews 5 words: `→ Sentence n/N: "…"`.
- **TUI history.** Every TUI sentence jump pushes history, because `_sentence_jump` calls `_history_push()` at `tui/mixin_navigation.py:22`. **GUI sentence jumps do not** (§4.4).

#### 3.2 Paragraph

- **TUI next** (`tui/mixin_navigation.py:218-229, 262-267`). From the `scroll` line (the viewport top, **not** the current word), it walks to the end of the non-blank run, then skips blank lines. It **clamps to the last line**: there is no "none" message and no wrap. It is scroll-only, via `_navigate_to` (`:198-210`), which restarts `_tts_play()` if speech was playing.
- **TUI previous** (`:231-244`). Skips blank lines backward, walks back through the previous run, then steps forward. It clamps at 0.
- **TUI replay** (`:98-129`). Finds the start of the paragraph containing `scroll`, then the first word with `disp_line >= that line`, and **always plays**.
- **GUI next and previous** (`_core.py:175-206`). Work on blocks from `_qt_current_block()` (the current word's block). Next says "No next paragraph" at the end. Previous clamps at 0.
- **GUI replay** (`_core.py:208-222`).

#### 3.3 Heading

**TUI** has two families:

- **Scroll only.** `h`, `}` and `{` → `_skip_next_heading` / `_skip_prev_heading` (`tui/mixin_navigation.py:326-347`). Speech resumes only if it was playing. "No heading below/above current position". No wrap.
- **Read.** `>` and `<` → `_read_next_heading` / `_read_prev_heading` (`:360-399`). These go through `_sentence_jump(..., always_play=True)`, so they always speak and push history.

A heading line is any rendered line with a segment role in `{"h1","h2","h3","h4"}` (`tui/theming.py:389`, `tui/mixin_navigation.py:212-216`). h5/h6 render as `h4` (`render.py:183`).

> **Bug (verified via `tui_view.heading_lines`: `[4,5,12,13,…]`).** The `═══`/`───` underline drawn under h1/h2 has role h1/h2 (`render.py:189-192`), so it **counts as a heading line**. "Next heading" pressed on an h1/h2 lands on its own underline.

**GUI** has only the **read** variant: `Ctrl+H` / `Ctrl+Shift+H` → `_qt_read_next_heading` / `_qt_read_prev_heading` (`_core.py:229-260`). They always play. A heading block is one with `blockFormat().headingLevel() > 0` (`:110-118`). The scroll-only pair was removed (`:224-227`).

**Contents panel** (`gui/mixin_toc.py:15-55`):

- It finds each `^(#{1,6})\s+(.*)` heading title in the rendered text with a rolling `QTextDocument.find`. The raw title still carries Markdown (`**`, links), so finding it can fail, or match earlier body text.
- A single click only scrolls (`:93-116`). A double click reads (`:118+`).

#### 3.4 Tables

- **TUI** `t`/`T` (`tui/mixin_navigation.py:276-324`). A table line is any line with role `table` (`tui/theming.py:392`).
  - Next skips the table it is in, then finds the next table line.
  - Previous finds the previous table, then walks back to its first line.
  - "No table below/above". Scroll only; speech resumes if it was playing.
- **GUI** `Ctrl+T`/`Ctrl+Shift+T` (`_core.py:264-315`). A table block is one whose `text().lstrip().startswith("|")` (`:264-273`). **But the Qt renderer turns every pipe table into an HTML `<table>`** (`gui/mixin_document.py:1006-1049`), so cell blocks never start with `|`. **GUI table navigation probably never finds a table (static; not run).**

#### 3.5 Speech Cursor (line mode)

**TUI** (`tui/mixin_speechcursor.py`):

- `Tab` enters the mode (`:15-42`). It starts at the highlighted line, or else the `scroll` line.
- Each move reads **exactly one display line** (`:71-102`). An empty line speaks the literal word **"blank"** (`:87-94`).
- Text is normalized with `_preprocess_tts_text` and **never** SSML.
- Moves clamp to `[0, total-1]` and **never wrap** (`:110`). The cursor keeps a `scroll_margin` of 3 (`:114-121`).
- Keys: see §6.2. On exit, the caret is set to the first word at/after the SC line (`:61-64`). `Enter` then reads on from there (`:65-69`).

**GUI** (`gui/mixin_navigation/_speechcursor.py`):

- `Tab`, caught in `eventFilter` (`:158-163`), toggles the mode.
- Up and Down move one **QTextBlock** (a paragraph or line) and read it (`:277-285, 309-341`). An empty block speaks "blank" (`:325-333`).
- `Enter` exits and reads on (`:171-173, 243-273`). `Esc` exits (`:168-170`).
- Moves clamp and do not wrap (`:283`).

#### 3.6 Caret (TUI)

- **Word moves.** Left/Right move by word and clamp (`tui/mixin_caret.py:110-117`).
- **Line moves.** Up/Down go to the nearest word on the next line that has words, with a sticky goal column (`:119-133`).
- **Page moves.** PgUp/PgDn move `h-4` lines (`:135-151`).
- **Ends.** Home/End go to word 0 or the last word (`:153-167`).
- **Reading.** `Enter`/`Ctrl+Space` read from the caret (`:171-178`).
- **Following speech.** The caret follows speech unless it was moved in the last 3 seconds (`_CARET_GRACE_S`, `:26`; `tui/mixin_playback.py:30-34`).

#### 3.7 Wrap behaviour (all verified from code)

| Operation | Wraps? |
|---|---|
| Search next/previous (TUI and GUI) | **Yes**, `(idx ± 1) % n` (`search.py:65-75`; `gui/mixin_find.py:373-389`) |
| Sentence, paragraph, heading, table, chapter, Speech Cursor, caret | **No** (clamp, or a "No …" message) |

#### 3.8 Chapters (TUI only)

- **Keys.** `F10` previous, `F11` next, `F12` list; `M-x chapter-goto N|title` (`tui/mixin_bookmarks.py:179-278`).
- **Previous rule.** More than 5 words into a chapter rewinds to the chapter start (`:219`: `if cur - ch_start_word > 5`).
- **Bug: every chapter index is 0.** `doc.chapters` is filled as `[(t, h, 0)…]` (`dispatch.py:316`, `handlers.py:85`), and no code ever maps `href` to a word index. So every chapter starts at word 0: "next" always says "Already at the last chapter", and "prev" jumps to word 0.
- **Double push.** Chapter and bookmark jumps call `_history_push()` and then `_sentence_jump`, which pushes again (`:197-198, 227-228, 260-261, 273-274`; bookmark `:64-65`). Each such jump records **two identical history entries**.
- **GUI.** There is no chapter navigation; the Contents panel is the substitute.

#### 3.9 TUI display model (what line-based navigation walks over)

`render_markdown(md, width)` (`star/render.py:127-295`), with width = `wrap_width` or `terminal_cols - 2` (`tui/mixin_document.py:113`):

| Markdown | TUI display |
|---|---|
| Heading | `# text` + underline (h1 `═`, h2 `─`) + blank line |
| List item | `  • ` / `  1. ` per item. **Nesting is flattened.** |
| Table row | One display line per row: `│ a │ b │`, with `├─┼─┤` for the separator |
| Code | A box: `┌ lang ─┐`, `│ line`, `└──┘` |
| Block quote | `▌ ` |
| Image | `[img: alt]` |
| Paragraph | Joined lines, wrapped |

All of this is **verified**: see `tui_view.lines` in the parity JSON.

### 4. Position and history

#### 4.1 Saving the reading position

The same schema is used in `settings["reading_positions"][doc.path] = {"offset", "pct", "ts"}`:

- **`offset`** = `word_map[cur].tts_offset`, a character offset into `plain_text`.
- **`pct`** = `int(100 * offset / max(1, len(plain_text)))`, i.e. the **floor**.
- **`ts`** = `time.strftime("%Y-%m-%dT%H:%M:%S")`, local time with no zone.
- **Eviction.** When there are more than 200 entries, the 50 oldest by `ts` are evicted.

| UI | Code | When it saves |
|---|---|---|
| TUI | `tui/mixin_navigation.py:133-155` | When a new document replaces the current one (`tui/mixin_document.py:49`), on quit (`tui/app.py:257`), and `M-x save-position` (`tui/mixin_commands.py:257`). **Never for the welcome page** (`:137-138`). |
| GUI | `gui/mixin_navigation/_position.py:20-49` | In `_open_path` (`gui/mixin_document.py:97`), on **every stop and every pause** (`gui/mixin_playback.py:177`, since pause calls `_tts_stop`), and on close (`gui/main_window.py:1192`). **The GUI has no welcome-page guard**, so the welcome page's position is saved and restored. |

The GUI also calls `record_progress(settings, path, {offset, pct, ts})` to mirror the entry into the library sidecar (`_position.py:45-49`).

#### 4.2 Restoring

- **Rule.** Star takes the **first word with `tts_offset >= saved offset`**, or the **last word** if none qualifies:
  - TUI: `tui/mixin_navigation.py:172-177`
  - GUI: `_position.py:78-83`
  - The same rule is `_qt_word_for_offset` (`gui/mixin_bookmarks_qt.py:251-259`) and TUI `_jump_to_offset` (`tui/mixin_bookmarks.py:158-167`).
- **Gating.** Restore is gated on `tts_auto_resume` (True by default, `settings.py:297`). The TUI can be forced with `M-x jump-saved` (`force=True`).
- **Status message.** `Resumed at {pct}%  (saved {ts[:10]})`.
- **TUI:** restores only on the open path (`restore=True`, `tui/mixin_document.py:92-133`). A re-render instead keeps the first visible word as its anchor.
- **GUI:** restores on `_restore_signal`, after the word map is built (`main_window.py:556`).

#### 4.3 Sidecar vs local: newest timestamp wins (GUI only)

- **Sidecar file.** `<library_folder>/.star/progress.json`, keyed by the document path **relative** to the deepest containing library folder (`star/library.py:135-136, 271-289`).
- **Rule** (`_position.py:59-70`): `if isinstance(side, dict) and (not saved or str(side["ts"]) > str(saved["ts"])): saved = side`. This is a string comparison, so on a tie the local entry wins.
- **Writes** are debounced (0.5 s), locked, reconciled with `sync.merge_progress` under `sync_conflict_policy` (default `"newest"`), and atomic (`library.py:153-163, 203-268, 321-369`).
- **Inconsistencies:**
  - The **TUI neither writes nor reads the sidecar.**
  - `ts` has no timezone and 1-second granularity, so machines in different zones order entries wrongly.

#### 4.4 Navigation history

**State.** `_nav_history: List[int]` holds **TTS char offsets**. `_nav_hist_pos` is `-1` when at the live position.

- TUI: `tui/app.py:126-127`
- GUI: `gui/mixin_bookmarks_qt.py:26-33`
- **Size.** `nav_history_size` defaults to 50 (`settings.py:156`). It is trimmed to the last N (`tui/mixin_bookmarks.py:121-123`; GUI `:206-208`).

**Push** (`_history_push`, TUI `tui/mixin_bookmarks.py:105-123`, GUI `:188-208`). It records the **departure** offset (the current word) before a jump. If `_nav_hist_pos >= 0`, it **truncates the forward entries** (`hist[:pos+1]`) and resets the position to -1. There is no de-duplication.

**Back** (TUI `:125-141`, GUI `:210-229`):

- From the live position, back goes to `total-1`, the most recent departure. Otherwise it goes to `pos-1`. At 0 it says "No earlier history".
- The target is `_jump_to_offset` / `_qt_jump_to_offset`, which **does not push**.

**Forward** (TUI `:143-156`, GUI `:231-248`): `pos+1`. When that passes the end, `pos` becomes -1 with the message "History: at present position." **and no jump**.

**When an entry is recorded:**

| UI | Records a history entry |
|---|---|
| TUI | Every `_sentence_jump`: sentence next/prev/replay (even replay of the same sentence), read-next/prev-heading, bookmark goto (**twice**), chapter jumps (**twice**). **Not** recorded: paragraph, scroll-heading, table, search, goto-line, caret moves, restore. |
| GUI | **Only** `_qt_bookmark_goto` (`gui/mixin_bookmarks_qt.py:102`). Sentence, paragraph, heading, table, find, Contents panel and note jumps do **not** push. |

**Bugs:**

- The live position is never pushed before the first "back". So after Back, Forward cannot return to where you were: the last Forward only resets the pointer.
- The TUI records duplicate entries.
- The TUI and GUI record different events.
- Tests: `tests/test_search_nav.py:246-283` covers only push/branch/back and an empty stack. `tests/test_history.py` covers the **command log** (`gui/mixin_history.py`, cap 500 at `:28`), not navigation.

#### 4.5 Bookmarks

- **Storage.** `settings["bookmarks"][doc.path or doc.title][name] = {offset, pct, ts}`. Names are auto-generated as `mark1`, `mark2`, … (TUI `tui/mixin_bookmarks.py:14-38`; GUI `gui/mixin_bookmarks_qt.py:43-75`).
- **Goto differs between UIs.** The TUI picks the **closest** word by absolute distance (`:56-63`). The GUI picks the **first word at/after** the offset (`:101`).
- **Listing.** The TUI list is sorted by name (`:79`). The GUI list is sorted by pct (`:143-145`).

### 5. Search

| | TUI (`star/search.py:11-99`, `star/tui/mixin_search.py`) | GUI find bar (`star/gui/mixin_find.py`) |
|---|---|---|
| Haystack | **Each rendered display line separately** (`search.py:45-54`). **A match cannot span a wrapped line break.** | The editor's `toPlainText()` as one string (`:353`) |
| Case | Always insensitive (`q_lower`, `:44-47`) | "Match case" checkbox, off by default (`:84-89, 354`) |
| Regex | `M-x search-regex`, always `re.IGNORECASE`. An invalid pattern falls back to a plain search (`:77-99`). | None |
| Whole word | None | None |
| Overlapping matches | Yes (`col = pos + 1`, `:54`) | Yes (`_find_all`, `:481-500`; test `test_search_nav.py:42`) |
| Start | First match on a line `>= scroll`, else index 0 (`:55-62`) | First match `>=` cursor position, else 0 (`:363-368`) |
| Next/prev wrap | Always (`:65-75`) | Always (`:373-389`) |
| Incremental | No | Yes, on `textChanged` (`:64, 346-347`) |
| Keys | `Ctrl+F`, `n`/`N`, `F3`/`F4`, `Esc` clears | `Ctrl+F`, `Enter`/`F3` next, `Shift+Enter`/`Shift+F3` previous, `Esc` closes (`:294-343`) |
| History push | No | No |

- The docstring promises "fuzzy matching" (`search.py:12`), but no fuzzy matching exists.
- Match length is `len(query)`, measured on the **lowercased** text (`search.py:53`; GUI `:490-491`). Characters whose case mapping changes length (`İ`→`i̇`) shift the offsets.
- **Search-backward bug.** `M-x search-backward` passes `"backward"` (`tui/mixin_commands.py:181-185`), but `_do_search(query, direction)` **ignores `direction`** (`tui/mixin_search.py:30-40`). It is a forward search from `scroll`. `self.search_dir = "forward"` (`tui/app.py:87`) is never read. `SearchEngine` has no direction concept.
- **Bigger TUI bug (static; not run): TUI search never runs its query.** `_enter_minibuffer(..., mode="search", on_commit=…)` stores `on_commit` **only for `mode=="mx"`** (`tui/mixin_commands.py:25-35`). `_handle_search_key` then calls `getattr(self, "_mx_callback", None)` (`tui/mixin_search.py:60-62`):
  - In a fresh session that is `None`, so `Ctrl+F` + Enter does nothing.
  - After any use of M-x it is `execute_command`, or the last minibuffer callback, so the **query is run as an M-x command** ("Unknown command 'foo'").
  - This affects `Ctrl+F`, `M-x search`, `search-backward` and `search-regex`.
  - No test covers it (grep of `tests/` for `_do_search`/`_handle_search_key` finds none).
- **Replace (GUI, edit mode only)** (`gui/mixin_find.py:231-291`). Replace All works back-to-front over the **overlapping** match list, so a query like `aa` in `aaa` corrupts the text. `Enter` in the replace field replaces one match.
- **Menu tip vs code.** The menu tip promises "Ctrl+Enter reads aloud" (`gui/mixin_chrome.py:672`), but that is not implemented (`gui/mixin_find.py:294-343`).
- **Library full-text search** (`star/fulltext.py:176-214`): a case-insensitive substring search over cached `plain_text`, sorted by match count, with a 60-character snippet.

**The TUI Alt-key / ESC issue** (`mixin_keys.py:28-38`, `tui/text.py:182-183`, comments at `mixin_keys.py:137-144`):

- The cheat sheet and code comments say `Alt+.`, `Alt+,` and `Alt+;` work in the TUI. **They do not.**
- **Unix terminals.** Alt+key arrives as `ESC` followed by the key. The ESC branch reads the next key with a 100 ms timeout. Unless it is `x`/`X`, it **stops speech and throws the key away**, so `Alt+.` = stop.
- **Windows (`windows-curses`/PDCurses).** Alt combinations arrive as distinct `ALT_*` key codes above 255. No code handles them, so nothing happens.
- **Speech Cursor mode.** `Alt+.` → ESC exits SC mode, and then `.` runs as a **normal-mode** next-sentence.
- **Lost keys.** A bare Esc followed within 100 ms by any key also loses that key.
- **`ESCDELAY`.** `ESCDELAY=25` is set before `curses.wrapper` (`star/app.py:434`). The second `setdefault` inside `StarApp.__init__` (`tui/app.py:168`) comes after `initscr` and does nothing.

### 7. Known bugs and quirks to fix rather than copy

Items marked **V** were verified by running Star.

**Loading and canonical text**

1. **V: Native HTML is empty after any unclosed `<meta>`, `<link>` or `<base>`.** Cause: `_SKIP` has no void-element handling (`html.py:8-26, 53-55`). Fix: treat void elements as non-containers.
2. **V: `_HTML2MD` quirks.**
   - The nested-list parent loses its bullet (`:115-116, 170-181`).
   - `<caption>` is dropped (`:194`).
   - `<title>` and `<h1>` duplicate the heading (`:251-254`).
   - An `<img>` directly followed by a block element merges paragraphs.
   - `<br>` becomes a space in speech.
3. **V: `^\s*` in the list-marker regexes crosses lines** (`ttstext/markdown.py:29-30`). Headings merge into following lists, and ordered and unordered lists merge together. Use `^[ \t]*`.

### 1. Highlight pacing and playback state machine

#### 1.1 Architecture in one paragraph

`TTSManager` (built from three mixins at `manager/__init__.py:38`) owns one active backend, the document word map (`List[WordPos]`), and a **timer thread** that is the primary highlight source for every backend (`_playback.py:183-184`). For two backend classes, `Pyttsx3Backend` and `ESpeakLibBackend` (`_playback.py:84`), the manager also passes an `on_word(location, length)` callback. That callback never paints: it only records the engine-confirmed word (`_last_cb_word_idx`, `_last_cb_time`) and monotonically advances the shared estimate `_current_word_idx` (`_playback.py:96-138`). The timer reads those fields to pace itself. Every other backend (applesay, qtspeech, DECtalk, festival, espeak CLI, piper, coqui, cloud, silent) gets timer-only highlighting, including qtspeech, which *does* emit accurate word events (see 3.3).

#### 1.2 Word map (the unit the highlight counts in)

- `WordPos(word, tts_offset, tts_len, disp_line, disp_col)` (`model.py:8-16`). `tts_offset` and `tts_len` are character offsets into `doc.plain_text`.
- Tokenizer: `_WORD_TOKEN_RE = re.compile(r"\b\w[\w'-]*")` (`model.py:36`). Word index *i* = the *i*-th match of this regex over `doc.plain_text` (`model.py:124`). Consequences: `6,423` is two tokens (`6`, `423`); `-15.3` is `15`, `3`; `twenty-four` is one token; `don't` is one token.
- Display mapping uses difflib alignment. See 5.6.

#### 1.5 `speak(text, start_word_idx=0, text_offset=0)` sequence (`_playback.py:39-184`)

1. `_timer_gen += 1`, then `_timer_stop.set()`. The generation is bumped **before** signalling the old timer (`:62-68`).
2. `_current_word_idx = max(0, start_word_idx)`, `_last_cb_word_idx = -1`, `_last_cb_time = 0.0` (`:69-71`).
3. Define the `on_done` closure (`:73-79`): `_timer_stop.set()`; `_current_word_idx = -1`; `_on_highlight(-1)` if set; `_on_done()` if set. **There is no generation check.**
4. If the backend is `Pyttsx3Backend` or `ESpeakLibBackend` (`:84`):
   - `_paced_playback = isinstance(ESpeakLibBackend)` (`:90`). If paced, call `backend.set_highlight_offset_ms(int(settings.get("espeak_highlight_offset_ms", 120)))` (`:91-94`).
   - `on_word_cb(location, length)` (`:96-138`):
     - If `text_offset < 0` (SSML mode sentinel), return immediately (`:113-114`).
     - `abs_loc = location + text_offset` (`:115`).
     - **Linear scan** over the entire word map: the first `i` with `wp.tts_offset <= abs_loc < wp.tts_offset + wp.tts_len + 1` (`:116-117`). The `+1` admits the one character after the word. The `length` argument is ignored.
     - On a hit, always set `_last_cb_word_idx = i` and `_last_cb_time = monotonic()` (`:127-128`). Then, only if `i >= _current_word_idx`, set `_current_word_idx = i` (`:136-137`). On a miss, nothing happens.
   - `_expect_callbacks = True` (`:140`). Call `backend.speak(text, on_word=on_word_cb, on_done=on_done)` (`:141`).
5. Otherwise (`:142-181`): `_expect_callbacks = False` and `_paced_playback = False`.
   - If the backend has `last_error` (cloud backends), wrap `on_done` (`:153-171`). Capture `_cloud_gen = _timer_gen`. On done, if `last_error` is non-empty **and** `_timer_gen == _cloud_gen`, set `last_engine_error = f"Cloud voice failed ({err}) — using a local voice"`, call `_select_backend("auto")`, then `self._backend.speak(text, on_done=orig)` (no `on_word`, no timer restart) and return. Otherwise call `orig()`.
   - `backend.speak(text, on_done=final_on_done)`. On a synchronous `CloudTTSError`, call `_select_backend("auto")` and then `backend.speak(text, on_done=on_done)` (`:172-181`).
6. **Always** `_start_timer_highlight(start_word_idx)` (`:183-184`).

#### 1.6 Timer thread `_tick` (`_playback.py:186-330`)

```
_timer_stop.clear()                       # :199
my_gen = _timer_gen                       # :202
interval = 60/max(1, rate*max(0.1,hl))    # :203-209
MAX_AHEAD = 1 if paced else 4             # :221
thread:
  deadline = now+10
  while not stop: if word_map: break; if now>deadline: return; sleep(0.05)   # :248-254
  if _timer_gen != my_gen: return                                           # :257
  if _expect_callbacks:                                                     # :269-278
      anchor_deadline = now+0.75
      while not stop:
          if gen changed: return
          if _last_cb_word_idx >= 0: break      # anchored on first real event
          if now > anchor_deadline: break       # give up, free-run
          sleep(0.01)
  idx = max(0, start_idx)                                                   # :280
  while not _timer_stop.wait(interval):     # first paint happens AFTER one interval  # :281
      if _timer_gen != my_gen: return                                       # :283
      if _current_word_idx > idx: idx = _current_word_idx   # adopt engine lead      # :287-288
      if _last_cb_word_idx >= 0:                                            # :308-314
          cb = _last_cb_word_idx; age = now - _last_cb_time
          if idx > cb and age < 1.5:  idx = cb          # FRESH: clamp back to truth
          elif idx > cb + MAX_AHEAD and age < 6.0: continue   # PAUSE: hold, no paint
          # else DEAD (age >= 6.0) or within slack: fall through (free-run)
      if idx < len(word_map):                                               # :315
          if _timer_gen != my_gen: return        # second gen check      # :320-321
          _current_word_idx = idx                                           # :322
          _on_highlight(idx)                                                # :323-324
          idx += 1                                                          # :325
      # at/after end: loop keeps running until _timer_stop is set (:326-327)
```

The three regimes, when `_last_cb_word_idx >= 0`:

| Callback age | Condition | Action |
|---|---|---|
| `< 1.5 s` (fresh) | `idx > cb` | `idx = cb`, then paint `cb`. Because `idx += 1` after each paint, the next tick is `cb+1 > cb` and is clamped again. **With a fresh stream the timer re-paints the same confirmed word every tick and never leads the engine.** `_MAX_AHEAD` has no effect in this regime. |
| `1.5 s ≤ age < 6.0 s` (pause) | `idx > cb + MAX_AHEAD` | Skip (hold, no paint). The timer can still paint up to `cb + MAX_AHEAD` inclusive. |
| `≥ 6.0 s` (dead) | none | Free-run: paint `idx` and increment. |
| never fired (`cb == -1`) | none | Free-run (SSML mode, or any backend without events). |

"Estimate formula", stated exactly: position(t) advances by one word per `interval` seconds, starting at `start_idx` and first painted at t ≈ `anchor_wait + interval`. The next index to paint is `idx ← max(idx, _current_word_idx)`, then the regime rule above is applied. No per-word duration model exists: word length, punctuation, and pauses are ignored.

#### 1.8 Pause and resume

No backend implements a real pause. A pause is a stop plus a saved word index. A resume is a new `speak()` of the document sliced from that word.

- GUI `_tts_toggle` (`gui/pb:140-167`) and TUI `_tts_toggle` (`tui/pb:124-152`):
  - If `speaking` (the backend's `speaking` property): `saved = last_cb_word_idx if >= 0 else current_word_idx` (`gui/pb:153-154`, `tui/pb:139-140`). This is read **before** stop, because `stop()` resets both fields. Then the code stops (the GUI also saves the reading position and announces "Paused"). If `saved >= 0`, it sets `_tts_paused_at_word = saved`.
  - Else, if `_tts_paused_at_word >= 0`: clear it and call `_tts_play_from_word(w)`.
  - Else: `_tts_play()` (GUI starts from word 0, `gui/pb:67-88`; TUI starts from the caret or top-of-screen word, `tui/pb:64-81`).
- `_tts_play_from_word(word_idx)`: `text_offset = wm[word_idx].tts_offset`. If the index is invalid, both become 0. `text_slice = plain_text[text_offset:]`, then `speak(text_slice, start_word_idx=word_idx, text_offset=text_offset)` (GUI `gui/pb:90-112`; TUI `tui/pb:83-114`, which adds normalization and SSML, see 5).
- Design intent (comments at `tui/pb:135-139`): the callback position may repeat a word or two on resume but never skips one.
- Chunking at the manager level: **none**. The whole remaining document (`plain_text[offset:]`) is one utterance handed to the backend. Only `ESpeakLibBackend` chunks internally (2.3). pyttsx3 receives the entire remainder in one `say()`.

#### 1.9 `on_done` handling

- The manager's `on_done` sets `_timer_stop`, sets `_current_word_idx = -1`, emits `_on_highlight(-1)` (the GUI clears the highlight, `gui/pb:237-239`; the TUI clears its fields, `tui/pb:47-51`), then calls `_on_done`.
- **Nothing in the app calls `set_on_done`.** A repository-wide grep finds only the definition (`_playback.py:36`) and one test. End-of-document therefore has no app-level behavior beyond clearing the highlight.
- The timer does not stop at the end of the word map (`_playback.py:326-327`). It relies on `on_done` to set `_timer_stop`.
- Backends that fire `on_done` **synchronously inside `speak()`** (SilentBackend `star/tts/silent.py:21-22`; any unavailable backend, for example `espeak.py:31-34`, `:451-454`; qtspeech without an engine) run it *before* `_start_timer_highlight` clears `_timer_stop` (`_playback.py:184`→`:199`). The timer then free-runs through the whole document with no audio and never stops until the next `speak()` or `stop()`. See Bug B3.
- Backend-level `on_done` guards:

| Backend | Behavior |
|---|---|

#### 1.10 Stop and shutdown

- `stop()` (`_playback.py:332-340`): `_timer_gen += 1`, `_timer_stop.set()`, `backend.stop()`, then reset `_current_word_idx`, `_last_cb_word_idx`, and `_last_cb_time`.
- `shutdown()` (`:342-362`): `stop()`, null `_on_highlight` and `_on_done`, join the timer and `backend._thread` (2.0 s each, never the current thread).
- `change_backend(name)` (`:382-385`): `stop()`, set `settings["tts_backend"]`, then `_select_backend(name)`.
- `set_rate(wpm)` (`:374-376`): writes the setting and calls `backend.set_rate`. It does **not** restart the timer. The interval was captured at timer start, so a mid-utterance rate change desynchronizes the timer until the next `speak()`.

### 2. eSpeak-NG integration

Two classes share `name = "espeak"`. Explicit selection tries the in-process library first (priority 40), then the CLI (priority 50) (`espeak.py:11`, `:207`; `_selection.py:55-61`).

#### 2.1 `ESpeakLibBackend` (in-process libespeak-ng through ctypes)

- **Library discovery** (`espeak.py:260-282`), in order:
  1. The vendored `_ESPEAK_NG_DLL` (`star/_runtime.py:193-194`: `_VENDOR/"espeak-ng"/"libespeak-ng.dll"`) with that directory as the data path.
  2. `ctypes.util.find_library("espeak-ng")` or `("espeak_ng")`, with data path None.
  3. Literal names `libespeak-ng.so.1`, `.so`, `libespeak-ng.1.dylib`, `.dylib`, `libespeak-ng.dll`.
- The library is loaded and initialized once, as class-level singletons guarded by a lock (`:216-257`).
- **Init** (`:362-367`): `espeak_Initialize(AUDIO_OUTPUT_PLAYBACK=0, buflength=0, path, options=0)`. A result `< 0` means try the next candidate.
- Constants (`:210-214`): `_AUDIO_OUTPUT_PLAYBACK=0`, `_CHARS_UTF8=1`, `_EVENT_WORD=1`, `_PARAM_RATE=1`, `_PARAM_VOLUME=2`. The event list terminator is type 0 (`:497`).
- **Synth mode:** `AUDIO_OUTPUT_PLAYBACK`. libespeak-ng plays audio itself. Per chunk:
  ```
  espeak_SetSynthCallback(cb)
  espeak_Synth(raw_utf8, len(raw)+1, 0, 0, 0, espeakCHARS_UTF8, None, None)
  espeak_Synchronize()      # blocks until that chunk has played
  ```
  (`:573-578`). There is **no SSML flag**: flags are `1` only.
- Per `speak()` (`:443-593`):
  - `stop()` first, then `_gen += 1`, `_speaking = True`, `_stop_evt.clear()`.
  - `espeak_SetVoiceByName(voice)`.
  - `SetParameter(RATE, clamp(rate, 80, 450))`.
  - `SetParameter(VOLUME, clamp(volume, 0, 200))` (`:460-468`).
- **Word event scheduling** (`:488-526`): for each `EVENT_WORD`, compute
  - `target = chunk_start + e.audio_position/1000.0 + self._hl_offset`
  - where `chunk_start = time.monotonic()`, captured just before `espeak_Synth` for that chunk (`:567`).
  - `audio_position` is milliseconds into that chunk's output stream (`:303`).
  - `_hl_offset` is the latency offset (default 0.12 s; the manager syncs it from `espeak_highlight_offset_ms`, default 120).
  - Each event is enqueued as `(target, base_offset + start_char, len_chars, my_gen)`.
  - Rationale (`:472-481`): in PLAYBACK mode, all of a chunk's WORD events arrive in a burst at synthesis time, well ahead of the audio.
- **Pacer thread** `_pace` (`:528-553`):
  - `get(timeout=0.2)`. On timeout, exit if stopped or the generation changed.
  - `None` means end.
  - Drop items whose generation is stale or that arrive while stopped.
  - `delay = target - now`. If `delay > 0`, `_stop_evt.wait(delay)` (interruptible).
  - Re-check the generation and stop state, then call `on_word(offset, length)`.
- **Worker end** (`:581-591`): `pace_q.put(None)`. Only if `_gen == my_gen`: `pacer.join(1.0)`, `_speaking = False`, `on_done()`.
- **stop()** (`:595-607`): `_gen += 1`, `_stop_evt.set()`, `_speaking = False`, `espeak_Cancel()`.

#### 2.2 Byte-to-char mapping (`espeak.py:421-440`, applied at `:505-520`)

- libespeak-ng reports `text_position` as **1-based** and `length` in **UTF-8 bytes** of the buffer it was given (`:299-302`).
- `_utf8_byte_to_char(chunk)` returns a list with one entry per UTF-8 byte (the character index that owns that byte), plus a final entry `len(chunk)`:
  ```
  out = []
  for i, ch in enumerate(chunk): out.extend([i] * len(ch.encode("utf-8","replace")))
  out.append(len(chunk))
  ```
- Mapping:
  ```
  last = len(b2c)-1
  b0 = min(max(text_position-1, 0), last)
  b1 = min(max(b0+length, b0), last)
  start = b2c[b0]; char_len = b2c[b1]-start
  ```
  Emitted as `(base_offset + start, char_len)`. `base_offset` is the chunk's character offset within the `speak()` text. The manager then adds `text_offset` (`_playback.py:115`).
- Worked value (observed): `_utf8_byte_to_char("Café pour Émile") == [0,1,2,3,3,4,5,6,7,8,9,10,10,11,12,13,14,15]`.

#### 2.3 Chunking `_chunk_offsets(text, max_len=400)` (`espeak.py:382-419`)

1. Split at every `_SENTENCE_SPLIT_RE` match. Segment `= text[pos : m.end()]`, so it **includes** the trailing whitespace or newlines. Then append the tail `text[pos:]`.
2. Drop whitespace-only segments.
3. A segment of length `<= max_len` is kept whole. Otherwise it is split greedily: `end = min(i+max_len, len)`. If `end < len`, take `sp = seg.rfind(" ", i+1, end)` and, if `sp > i`, set `end = sp+1` (the space stays with the left piece). Keep a piece if `piece.strip()`.
4. Return `out or [(text, 0)]`, so empty input gives `[("", 0)]`.

Observed examples:
```
"First sentence. Second sentence! Third?" -> [("First sentence. ",0),("Second sentence! ",16),("Third?",33)]
"Alpha beta. Gamma delta epsilon."        -> [("Alpha beta. ",0),("Gamma delta epsilon.",12)]
"Para one.\n\nPara two\nline two. lower case after. Next"
   -> [("Para one.\n\n",0),("Para two\nline two. lower case after. ",11),("Next",48)]
("word "*50).strip(), max_len=40 -> 6 x ("word word word word word word word word ", 0/40/80/120/160/200) + ("word word",240)
"" -> [("",0)]
```

#### 2.4 `ESpeakBackend` (CLI subprocess)

- Binary: `shutil.which("espeak-ng") or shutil.which("espeak")` (`espeak.py:19`).
- Rate: `int(wpm * 0.8)` (`:14`, `:131`). **The library backend passes wpm unscaled** (see 4).
- Volume: `-a int(vol*100)`. The constructor default is 100. `_construct_backend` does not pass a volume for espeak, so the manager's `set_volume` sets it afterward (`_selection.py:80`, `:95-96`).
- Command: `[bin, "-v", voice, "-s", rate, "-a", volume, ("-m" if ssml), "--stdin"]`, with the text written to stdin (`:65-111`).
- SSML auto-detect: `text.lstrip().startswith("<speak>")` (`:37`).
- Mark mode (`:45-59`), only if `on_word` is passed: wrap each whitespace-delimited token as `<mark name="N"/>token` inside `<speak>…</speak>`, then read `MARK N` lines from stdout and call `on_word(N, len(token))`, where **N is a word index, not a char offset** (`:88-101`). The manager never passes `on_word` to this class, so the path is dead in-app.
- `on_done` fires in `finally` with no generation guard (`:115-118`).

### 3. Backend selection

#### 3.1 Algorithm `_select_backend(preference)` (`_selection.py:32-82`)

- Classes come from the plugin registry, entry-point group `star.backends` (`star/plugins.py:29`, `:103-106`), sorted by `priority` ascending (`_selection.py:48`).
- **Explicit preference** (any value other than `""` or `"auto"`): try only classes whose `.name == preference`, in priority order. Construct each (3.4) and take the first with `available()` (`:51-61`).
  - **If none is available, the result is SilentBackend. There is no fallback to auto.** This includes unknown names such as `"none"`, which the settings comment lists (`settings.py:51`).
  - `"silent"` resolves to SilentBackend. The test registry lacks it, so it falls through to the Silent floor (`tests/test_tts.py:737-740`).
- **Auto** (`:62-76`): walk every class in priority order, skipping names in `_AUTO_SKIP = {"silent","piper","coqui","elevenlabs"}` (`manager/__init__.py:43`). Take the first available.
- Floor: `self._backend = chosen or SilentBackend()` (`:78`).
- Then `backend.set_rate(int(tts_rate))`, `backend.set_volume(float(tts_volume))` (`:79-80`), `_resolve_default_voice()` (`:81`), and `_resolve_language_voice()` (`:82`).
- Cloud and failure fallback: see 1.5 step 5. A cloud backend's `available()` is true iff an API key is configured (`star/tts/cloud/base.py:122-130`). With a present-but-invalid key it fails at speak time and the manager falls back to `_select_backend("auto")`. The setting is not changed.

### 5. Normalization pipeline

There are **four distinct text stages**. Only stage A output is indexed by the word map.

#### 5.A Load time: markdown to `doc.plain_text`

- Entry point: `_strip_markdown_for_tts(md, skip_code, table_mode)` (`star/ttstext/markdown.py:11-80`), called at `star/documents/handlers.py:32-38` and `star/documents/dispatch.py:305-309`.
- Arguments: `skip_code = settings["tts_skip_code"]` (default `True`, `settings.py:64`; **`False` when the settings object is None**, `handlers.py:32`) and `table_mode = settings.get("table_reading_mode","structured")` (`settings.py:285`).

Transforms, in order (all regexes use Python `re` semantics; `M` means MULTILINE):

1. List markers: `^\s*[-*+]\s+` → `""` (M), then `^\s*\d+[.)]\s+` → `""` (M) (`:29-30`). These run **before** the indented-code strip so 4-space nested list items survive. Quirk: `^\s*` spans newlines, so a blank line before a list item is also eaten (Q5).
2. Code:
   - If `skip_code`: `` ```[\s\S]*?``` `` → `""`; `~~~[\s\S]*?~~~` → `""`; `^    .+$` → `""` (M) (`:33-36`).
   - Else: `` ```\w*\n? `` → `""`, then `` ``` `` → `""` (`:37-39`).
3. Headings: `^#{1,6}\s+` → `""` (M) (`:42`).
4. Horizontal rules: `^(\*{3,}|-{3,}|_{3,})\s*$` → `""` (M) (`:45`).
5. Images: `!\[([^\]]*)\]\([^\)]*\)` → `\1`. Links: `\[([^\]]*)\]\([^\)]*\)` → `\1` (`:48-49`).

##### 5.A.1 `_tables_to_narration(text, mode="structured")` (`star/ttstext/tables.py:7-101`)

- An unknown mode becomes `"structured"` (`:24-25`).
- The text is processed by lines. A table block is a maximal run of lines that contain `|` **and** whose stripped form starts with `|` (`:33-42`). Other lines pass through unchanged.
- `skip`: count non-empty cells in the first block line, then emit `f"Table with {n} column{'s' if n!=1 else ''} \u2014 skipped."` followed by `""` (`:44-53`).
- Cell parse: `[c.strip() for c in line.strip().strip("|").split("|")]` (`:56-58`).
- Separator row: all non-empty cells match `^[-:]+$`, and the row is skipped (`:64-65`). Header = the first non-separator row with empty cells removed. The remaining rows are data rows with empty cells removed (`:66-70`). Because empties are removed, cells shift left (Q10).
- `flat`: for the header and each row, `".  ".join(cells) + "."`, then `""` (`:72-78`).
- `structured`:
  - `f"Table with {ncols} column{'s' if ncols!=1 else ''}: {', '.join(header)}."`
  - Each data row: `f"Row {ri}: " + ", ".join(f"{hdr} is {data[hi]}" for each header index with a non-empty cell) + "."`
  - Header-less data rows: `f"Row {ri}: {', '.join(cells)}."`
  - Then `""` (`:80-99`).
- Output: `"\n".join(result)` (`:101`).

##### 5.B.3 Numbers `_normalize_numbers(text)` (`star/ttstext/numbers.py:171-290`)

Applied in this order. Each step is a full `re.sub` over the output of the previous one.

1. **ISO date** `\b(\d{4})-(0[1-9]|1[0-2])-(0[1-9]|[12]\d|3[01])\b` → `"{Month} {ordinal(d)}, {year_words(y)}"` (`:187-191`).
2. **US date** `\b(0?[1-9]|1[0-2])/(0?[1-9]|[12]\d|3[01])/(\d{4})\b` → the same format; the month is zero-filled for lookup (`:194-200`).
3. **Time** `\b([01]?\d|2[0-3]):([0-5]\d)(?::\d\d)?\s*([AaPp][Mm])?` (`:223-225`). Rules (`:203-221`):
   - `h==0 and m==0 and no explicit` → `midnight`
   - `h==12 and m==0 and no explicit` → `noon`
   - explicit `PM` and `h<12` → `h12=h`, `PM`
   - explicit `AM` → `h12 = h%12 or 12`, `AM`
   - otherwise → `period = AM if h<12 else PM`, `h12 = h if h<=12 else h-12` (so `00:30` gives `zero thirty AM`)
   - Output: `"{int(h12)} {period}"` if `m==0`, else `"{int(h12)} {int(m)} {period}"`. Seconds are dropped.
   - **The `\s*` consumes trailing whitespace even when no AM/PM follows** (Bug Q1).
4. **Currency** `([$\u00a3\u20ac])(\d[\d,]*)\.?(\d{2})?` (`:248`).
   - Symbols: `$`→(dollar, cent), `£`→(pound, penny), `€`→(euro, cent).
   - `whole` has commas removed. `frac = (group3 or "00")[:2].ljust(2,"0")`.
   - Parts are `"{words(whole)} {major}{'s' if !=1}"` if whole is non-zero, and `"{words(frac)} {minor}{'s' if !=1}"` if frac is non-zero. They are joined with `" and "`. If both are zero: `"zero {major}s"`.
   - The minor plural is naive (`pennys`).
5. **Percent** `\b(\d+(?:\.\d+)?)%` → `"{int} percent"`, or `"{int or 'zero'} point {digits} percent"` (`:251-258`).
6. **Ordinals** `\b(\d+)(?:st|nd|rd|th)\b` (IGNORECASE) → `ordinal_words` (`:261-266`).
7. **Comma integers** `\b\d{1,3}(?:,\d{3})+\b` → `int_words` (`:269-273`).
8. **Decimals** `(?<![\d/\-])\b(\d+)\.(\d+)\b(?![-/\d])` → `"{int} point {digit words}"` (`:276-279`).
9. **Plain integers** `(?<!\.)\b(\d{4,})\b(?!\.)`: values in `1000..2099` go through `year_words`, others through `int_words` (`:282-288`). Integers below 1000 are left as digits.

Helpers:

- `_int_to_words(n)` (`:58-84`):
  - 0 → `zero`; negative → `"negative "+words(-n)`.
  - `<20` uses `_ONES`; `<100` is `TENS[t] + "-" + ONES[o]` when `o != 0`; `<1000` is `ONES[h] + " hundred" + (" "+words(r))`.
  - Then trillion, billion, million, and thousand via recursion; beyond that, `str(n)`.
  - There is no "and".
- `_year_to_words(y)` (`:87-105`):
  - Outside `100..2999` → `int_words`.
  - `y%100==0`: `y%1000==0` → `int_words` (`two thousand`), else `"{century} hundred"`.
  - `decade<10` → `"{century} oh {decade}"`, else `"{century} {decade}"`.
- `_ordinal_to_words(n)` (`:108-163`):
  - Specials 1 to 12; negative → `"negative "+ord(-n)`.
  - 13 to 19 → `words+"th"`.
  - 20 to 99: with a non-zero ones digit, `words(tens*10)+"-"+ord(ones)`; round tens use `words[:-1]+"ieth"`.
  - Below 1000: `words(h*100)+" "+ord(rest)`, or `words+"th"`.
  - Larger values: `words(q)+" "+label+" "+ord(r)`, or `words(q)+" "+label+"th"`.
- `_decimal_digits_to_words(d)` reads each digit (`0`→`zero`), space-joined (`:166-168`).

    - `(?<!&amp)(?<!&lt)(?<!&gt)(?<!&quot);(\s+)` → `;<break time="{clause_ms}ms"/>\1`
    - `[\u2014\u2013]` → ` <break time="{clause_ms}ms"/> `
    - wrap in `<speak>…</speak>`
- `_text_to_dectalk(text, 350, 150)` (`ssml.py:72-93`):
  - `([.!?\u2026])(\s+)` → `\1 [:pau {sentence_ms}] `
  - `([,;:])(\s+)` → `\1 [:pau {clause_ms}] `
  - dashes → ` [:pau {clause_ms}] `

#### 5.D Other text transforms touching speech

- `_build_subtitle_cues(text, duration, word_level=False, max_words=12, max_chars=90)` (`star/tts/subtitles.py:18-71`):
  - Tokens are `\S+`. Each token's weight is `len(tok)+1`; token times are the cumulative fraction of `duration`.
  - Word level gives one cue per token.
  - Otherwise tokens are grouped, breaking when a token starts at a `_SENTENCE_SPLIT_RE` `m.end()`, when `len(cur)>=max_words`, or when `cur_chars+len(tok)+1 > max_chars`.
- SRT/VTT formatting (`subtitles.py:6-15`, `:74-92`):
  - SRT time format `HH:MM:SS,mmm`; VTT uses `.` and a `WEBVTT` header.
  - Zero-length cues are nudged by +0.05 s.
  - Output is `"\n".join(...).strip() + "\n"`.

#### 5.6 Alignment of two text streams (difflib) and where offsets are lost

**`_align_word_offsets(spoken, rendered)`** (`model.py:39-101`):

- `spoken` is the lower-cased `_WORD_TOKEN_RE` token list of `plain_text`. `rendered` is `(lower_token, char_offset)` for the display text.
- Fast path: identical token lists return the rendered offsets (`:73-74`).
- Otherwise, chunked alignment with `CHUNK=2000`, `PAD=500` (`:76-77`):
  ```
  si=ri=0
  while si<n and ri<m:
     s_hi=min(n,si+2000); r_hi=min(m,ri+2000+500)
     sm=SequenceMatcher(None, spoken[si:s_hi], r_words[ri:r_hi], autojunk=False)
     blocks=[b for b in sm.get_matching_blocks() if b.size]
     if not blocks: si+=1000; ri+=1000; continue
     for each block (a,b,size): offsets[si+a+k] = rendered[ri+b+k].offset
     last=blocks[-1]; new_si=si+last.a+last.size; new_ri=ri+last.b+last.size
     if new_si<=si: new_si=s_hi
     si,ri=new_si,new_ri
  ```
- Unmatched spoken words get `-1`.
- **A Rust port must reproduce difflib's `SequenceMatcher.get_matching_blocks` exactly** (longest-matching-block recursion, with no autojunk) to get identical maps.

**Gap-fill:**
- In `_build_word_map` (`model.py:142-156`) and `_build_qt_word_map` (`star/gui/mixin_document.py:386-398`): a backward pass copies the next aligned offset into `-1` entries, then a forward pass fills the remaining trailing `-1` entries with the previous offset (initial `prev = 0`).
- The windowed variant (`star/gui/mixin_document.py:401-450`) aligns only `word_map[start:end]` words against the window text. It uses `prev = -1`, so it never invents 0, and words outside the window stay `-1`.
- `_build_word_map` converts blob offsets to `(line, col)` via `bisect_right(line_start, off)-1` (`model.py:158-163`). The line blob is the display lines joined with `"\n"`.

**Where offsets are lost or drift:**

1. **Spoken-only narration** (table narration, "Row 1", "… is …") aligns to `-1`, and gap-fill parks those words on the next real word. During table narration the highlight sits still on the first cell and then jumps.
2. **Speak-time normalization in the TUI** changes the string the engine receives, while `text_offset` and the word map still refer to the *un-normalized* `plain_text` (`tui/pb:94-114`). pyttsx3 or espeaklib callback `location` values index into the normalized slice, so `abs_loc = location + text_offset` drifts by the cumulative length delta of every expansion before that point. Examples: `Fig.`→`Figure` is +2 characters, and `$1,234.56` becomes 72 characters. The word-map scan then matches the wrong word or misses. The pause position (`last_cb_word_idx`) inherits the error, so resume can skip or repeat text.
3. **Word-count mismatch:** the timer counts `plain_text` tokens, but the engine speaks the normalized tokens. `2024` is one map word but two spoken words; `$5` is one map word (`5`) but two spoken words. So the free-running timer runs ahead of the audio after every expansion.
4. **SSML mode** (TUI, `use_ssml`) passes `text_offset=-1`, so every callback is dropped (`_playback.py:113-114`) and the highlight is timer-only. For pyttsx3 and espeaklib, `_expect_callbacks` is still True, so the first paint is **always** delayed the full 0.75 s anchor timeout.
5. **Math normalization** `.strip()`s the entire slice and collapses double spaces globally (`mathspeech.py:129-130`). Any leading whitespace or double-space run in the slice shifts every later offset.
6. **eSpeak byte offsets** are fixed per chunk by the byte-to-char map (2.2). Correct as long as the text reaching libespeak-ng is exactly the chunk string.
7. **`on_word_cb` window** `tts_offset <= abs_loc < tts_offset+tts_len+1` (`_playback.py:117`): a callback whose location lands on leading punctuation (for example `"` or `(` before a word) or on the second of several spaces matches nothing and is dropped silently.
8. **Pathological alignment chunks** with no common token skip 1000 tokens on both sides (`model.py:86-91`). Those words stay `-1` and get gap-filled.

### 7. Known bugs and quirks (fix rather than copy)

#### 7.1 Playback and highlight

- **B1. `on_done` has no generation check, and `_timer_stop` is one shared Event** (`_playback.py:73-79`, `:57`, `:199`).
  - The espeak CLI, applesay, DECtalk DLL and CLI, and festival fire `on_done` in `finally` with no guard. Piper, coqui, and cloud guard only with a flag the next `speak()` clears.
  - A superseded utterance's `on_done` can therefore arrive after the new timer cleared `_timer_stop`. It sets the Event, which kills the *new* timer, sets `_current_word_idx=-1`, and paints `-1`. The same path fires on every user `stop()` for those backends.
  - Fix: capture the generation per utterance, ignore stale `on_done` and `on_word`, and give each timer its own stop token.
- **B2. `on_word_cb` has no generation check** (`_playback.py:96-138`). Late pyttsx3 events from a superseded engine pass `_stop_requested` (`pyttsx3.py:233`) because the next `speak()` resets it, so they overwrite `_last_cb_word_idx`.
- **B3. Synchronous `on_done` before the timer starts.** SilentBackend and every unavailable backend call `on_done` inside `speak()`, before `_start_timer_highlight` clears `_timer_stop` (`_playback.py:141`/`:173` → `:184` → `:199`). The highlight then free-runs through the entire document with no audio, and the thread never ends until the next stop or speak. `speaking` stays False, so Space never "pauses" either (`gui/pb:148`).
- **B4. The timer never exits at the end of the map** (`_playback.py:326-327`). It spins until `on_done` or `stop()`.
- **B5. Fresh-callback regime repaints the same word every tick** (`_playback.py:311-312`, `:315-325`). `_on_highlight(cb)` fires every `interval` with an unchanged index, which causes redundant GUI repaints and scroll checks. `_MAX_AHEAD` is effectively dead in that regime.
- **B6. Default `highlight_lead_words = 1`** (`settings.py:262`) paints one word ahead of the engine-confirmed word in the GUI. The code comment at `_playback.py:298-299` treats lead as opt-in. The TUI ignores lead entirely.
- **B7. QtSpeech word events are discarded.** They are accurate `(offset, len)` pairs (`qtspeech.py:191-213`), but the manager wires callbacks only for pyttsx3 and espeaklib (`_playback.py:84`). Fix: capability flags on the backend trait (`emits_word_events`, `paced`) instead of `isinstance`.
- **B8. `on_word_cb` is O(n) per event** (a linear scan over the whole word map, `_playback.py:116`). Use a binary search on `tts_offset`.
- **B9. Rate changes mid-utterance do not update the timer interval** (captured at `_playback.py:203-209`). pyttsx3 applies the new rate live (`pyttsx3.py:288-295`), so highlight and audio diverge until the next `speak()`.
- **B10. Cloud fallback retry** (`_playback.py:157-169`, `:174-181`):
  - The retry speaks on the fallback engine with no `on_word` and without restarting the timer. The old timer has been free-running during the failed cloud synthesis.
  - `_on_done_cloud` calls `orig()` even for a stale generation.
  - The switch to the auto backend is silent and session-only (`settings["tts_backend"]` stays `elevenlabs`).
- **B11. Explicit preference unavailable → SilentBackend, with no auto fallback** (`_selection.py:51-61`, `:78`). Choosing `piper` without a model, or `elevenlabs` without a key, gives a silent reader with a moving highlight.
- **B12. SSML mode always waits the full 0.75 s anchor** before the first paint for pyttsx3 and espeaklib. `text_offset=-1` drops every callback, but `_expect_callbacks` is still True (`_playback.py:113-114`, `:140`, `:269-278`).
- **B13. The first paint is always delayed by one `interval`**, because the loop is `wait(interval)` then paint (`_playback.py:281`). The start word is not shown immediately.
- **B14. espeaklib with SSML.** `espeak_Synth` is called without `espeakSSML` (flags=1, `espeak.py:575-577`), and `_chunk_offsets` would split the SSML markup mid-tag at sentence boundaries. SSML is therefore not usable with the in-process backend (the TUI will send it when `use_ssml` is on).
- **B15. Pacer join timeout 1.0 s** (`espeak.py:588`). If it expires, `on_done` fires while the pacer can still emit `on_word`, which re-sets `_current_word_idx` after it was set to -1.

#### 7.2 Text offsets and normalization

- **N1. TUI offset drift** (`tui/pb:101-114`). The normalized text is sent with the un-normalized `text_offset`, so every callback after the first expansion maps to the wrong word, and so does the pause position (5.6 item 2). The GUI avoids this only by **not normalizing at all** during playback, so GUI readers never get abbreviations, numbers, or math expansion (`gui/pb:78-83`, `:100-106`). Fix: normalize with an offset map (build the normalized string alongside a normalized-to-source index), or normalize per word.
- **N2. Map versus spoken word-count mismatch.** The timer counts source tokens while the engine speaks expanded tokens (5.6 item 3).
- **Q1. The time regex eats trailing whitespace and unbounded "am"/"pm" letters** (`numbers.py:224`). Observed:
  - `"at 3:45 today"` → `"at three forty-five AMtoday"`
  - `"3:00 amazing"` → `"three AMazing"`
  - `"John 3:16 says"` → `"John three sixteen AMsays"` (Bible verses and ratios are read as times)
  - `"08:05"` → `"eight five AM"` (no "oh")
  - `"13:00 PM"` → `"one PM"`
  - Seconds are dropped: `"10:30:15"` → `"ten thirty AM"`.
- **Q2. Currency** (`numbers.py:248`):
  - `"It costs $5."` → `"It costs five dollars"` (the sentence period is consumed by `\.?`).
  - `"$3.14159"` → `"three dollars and fourteen cents159"`.
  - The minor unit plural is naive (`pennys`).
- **Q3. Decimals and years at punctuation** (`numbers.py:279`, `:288`):
  - `"in 2024."` → unchanged (the `(?!\.)` lookahead blocks a sentence-final year).
  - `"1,234.5"` → `"one thousand two hundred thirty-four.5"`.
  - `"192.168.1.1"` → `"one hundred ninety-two point one six eight.one point one"`.
  - `"v1.2.3"` → `"v1.two point three"` (pinned by a test).
  - `".5"` and `"-5"` are unchanged; there is no negative-number handling.
  - `"the 2020s"` is unchanged.
- **Q4. Abbreviations fire on ordinary sentence-final words** (case-sensitive `\b` + literal, no context). `"I said no."` → `"I said number"`, and likewise `ed.`, `min.`, `max.`, `est.`, `sec.`, `temp.`, `p.`. `No. 5` works. `"e.g."` uses `\b` before `e`, so it matches mid-token after a non-word character. Custom expansions use `re.sub` templates, so backslashes in user text are interpreted.
- **Q5. List-marker regex eats blank lines** (`markdown.py:29-30`, `^\s*` spans newlines). A paragraph break before a list is lost. Observed: `"para\n\n\n- a\n- b"` → `"para a b"`, and test T1's list merges into the preceding paragraph.
- **Q6. Underscore and emphasis rules mangle identifiers.**
  - Markdown `_…_` strip: `"my_var_name and 2*3*4"` → `"myvarname and 234"`.
  - In the speak pipeline, math subscripts apply to prose: `"snake_case word"` → `"snake sub case word"`, and `"my_var_name is x"` → `"my sub var sub name is x"`.
  - `normalize_math` defaults to on (`settings.py:277`) and has no guard for "is this actually math".
- **Q7. `x^2` at the end of the string** → `"x to the 2"`, because `(?=\W)` needs a following character (`mathspeech.py:33-34`). Use `(?!\w)`.
- **Q8. Math cleanup is global.** It removes every `{`/`}`, collapses every double space, `.strip()`s the slice, and turns any `$…$` pair in prose into bare text (`"$5 and $10"` → `"5 and 10"` when numbers are off) (`mathspeech.py:15-18`, `:127-130`). Greek replacement has no word boundary (`:75-76`).
- **Q9. SSML escaping** omits `'`. The escaped `&quot;` and similar remain inside the plain-text semantics. Breaks are inserted after `:` in times such as `3:45` only when followed by whitespace, which is fine, but also after `,` in numbers such as `1, 2`.
- **Q10. Tables** (`tables.py:66-70`, `:87-91`): empty cells are removed from rows **before** header pairing, so a blank middle cell shifts later cells under the wrong headers. Rows with more cells than headers silently drop the extras. A line must *start* with `|` to count as a table (GFM tables without a leading pipe are missed).
- **Q11. `_resolve_default_voice` "US" test is a substring** (`"us" in lang.lower()`, `_selection.py:141-144`). This also matches `rus`, `aus`, and similar.
- **Q12. The GUI SSML toggle has no effect on GUI playback** (only the TUI calls `_text_to_ssml`). The Preferences volume spin uses `float(v or 1.0)`, so a stored volume of `0.0` displays as 100 % (`star/gui/preferences.py:564-568`). The rate spin caps at 400 while the keys allow 600.
- **Q13. Pipeline docstring is stale.** It lists three steps and omits math (`pipeline.py:16-19`). `handlers.py:32` defaults `skip_code=False` when settings is None, while the function default is True.
- **Q14. espeak rate is inconsistent between implementations.** The CLI speaks at 0.8×wpm and the library at 1.0×wpm clamped 80 to 450, so the same `tts_rate` sounds different depending on which espeak was found (`espeak.py:14` versus `:463`).
- **Q15. Volume ignored** by applesay, festival, DECtalk (both), and ElevenLabs. Rate ignored by ElevenLabs. No pitch anywhere.
- **Q16. Stale comments and docs.** `pyproject.toml:181-185` (qtspeech "not registered"), `qtspeech.py:107-111` (wrong priorities), `manager/__init__.py:76-82` and `_playback.py:264-265` ("only pyttsx3 sets `_expect_callbacks`"), and `test_highlight_pacing.py:48` ("+4").

### 2. Per-document state

All of this lives inside `settings.json`, except the sidecar (§3), the parse cache (§2.7), and recovery snapshots (§5). **Document keys are not consistent between stores:**

| Store | Key used | Cite |
|---|---|---|
| `reading_positions`, `reading_stats`, `library` | `doc.path` exactly as opened (not resolved or normalized) | `gui/mixin_navigation/_position.py:33`, `stats.py:117,144` |
| `bookmarks`, `annotations` | `doc.path or doc.title` | `gui/mixin_bookmarks_qt.py:36-40`, `gui/mixin_annotations.py:19-23`, `tui/mixin_annotations.py:15-19`, `tui/mixin_bookmarks.py:19` |
| `user_highlights` | `doc.path or "__no_path__"` | `gui/mixin_highlights.py:71,108,127` |
| sidecar | POSIX path relative to the deepest containing library folder (both sides resolved) | `library.py:271-289` |
| recovery snapshot | `"doc-" + sha1(abspath)[:16]`, or `"untitled-" + window_id` | `gui/mixin_autosave.py:44-53` |
| parse cache | `md5(path)[:16]` | `cache.py:12-15` |

All timestamps are `time.strftime("%Y-%m-%dT%H:%M:%S")`: **local time with no zone**.

#### 2.1 `reading_positions`: `{path: {"offset": int, "pct": int, "ts": str}}`

- `offset` is the TTS plain-text char offset of the current word (`word_map[cur].tts_offset`). `pct = int(100*offset/max(1,len(plain_text)))` (`gui/mixin_navigation/_position.py:29-37`).
- Saved on stop, on close (`gui/main_window.py:1192`), and elsewhere. Skipped if the doc has no path or no word map. The TUI also skips the welcome page (`tui/mixin_navigation.py:137`). The GUI does not have that check.
- **Cap:** when there are more than 200 entries, the 50 with the oldest `ts` are evicted (string sort) (`_position.py:38-41`, `tui/mixin_navigation.py:151-154`).
- The GUI mirrors each save to the sidecar through `record_progress` (`_position.py:45-49`). **The TUI never touches the sidecar**: no `record_progress` or `progress_for` calls exist under `star/tui`.
- Restore (GUI) runs only if `tts_auto_resume` is on. It prefers the sidecar entry when `str(side.ts) > str(saved.ts)` and ignores `sync_conflict_policy`. The target word is the first word with `tts_offset >= offset`, else the last word. Status: `Resumed at {pct}%  (saved {ts[:10]})` for 5 s (`_position.py:51-99`). The TUI shows the same text through `notify` (`tui/mixin_navigation.py:157-182`). The TUI "clear position" command reports `Reading position cleared` or `No saved position for this document` (`:184-194`).

#### 2.2 `bookmarks`: `{docKey: {name: {"offset","pct","ts"}}}`

- An empty name auto-generates `mark1`, `mark2`, ... using the first free `markN`. Offset and pct are computed as in §2.1 (`gui/mixin_bookmarks_qt.py:43-75`, `tui/mixin_bookmarks.py:14-38`). No cap.
- Status on add: `Bookmark set: {name}  ({pct}%)`. Ctrl+M adds (Ctrl+B moved to Bold, `tests/test_authoring.py:229-247`).

#### 2.3 `annotations`: `{docKey: [annotation]}`

Annotation dict fields (`settings.py:126`, `gui/mixin_annotations.py:150-159`):

| Field | Meaning |
|---|---|
| `char_pos` | int, Qt rendered-document char position. The TUI always writes `0` (`tui/mixin_annotations.py:75`) |
| `word_idx` | int, word-map index |
| `anchor` | Selected text, or the cursor's paragraph. Whitespace is collapsed and the value is truncated to 120 chars (`:111-126`) |
| `note` | Stripped text. Empty text on edit deletes the note (`:190-192`) |
| `tags` | list[str], from `_parse_tags`: split on `[,\s]+`, leading `#` stripped, empties dropped (`annotations.py:143-146`) |
| `cite` | str, `""` on creation |
| `ts` | Updated on edit |
| `id` | Optional. **Not assigned on creation**. Assigned lazily as `uuid4().hex[:8]` by `_ensure_id` when graph or review code touches the note (`annotations.py:175-181`) |
| `relations` | Optional: `[{rel_type, target_doc, target_id, note}]` (`annotations.py:194-229`). `rel_type` is one of `CONFLICTS_WITH`, `SUPPORTS`, `IS_EXAMPLE_OF`, `CITES`, `CONTRADICTS`, `DEFINES`, `EXTENDS`, `SEE_ALSO`, `PRECEDES`, `FOLLOWS` |
| `sr_state` | Optional spaced-repetition dict (`annotations.py:279-338`) |

- Storing an empty list removes the key (`gui/mixin_annotations.py:44-49`). The stored list is re-sorted by `char_pos` (GUI) or by `word_idx`, falling back to `char_pos` (TUI).
- Search (`_annotation_matches`, `annotations.py:115-140`) ANDs space-separated terms, case-insensitively. A term `#x` matches any tag containing `x`. Any other term must be a substring of the note, the anchor, or a tag. An empty query matches everything.
- Export formats: `.json`, `.bib`, `.ris` (CRLF line endings), `.txt`, and `.md` as the default (`annotations.py:5-112`).

#### 2.4 `user_highlights`: `{docKey: [{"start": int, "end": int, "color": str}]}`

- Offsets are **Qt rendered-document char offsets** (`gui/mixin_highlights.py:32-33,74`). The default color is `#ffff00`. There is no id and no ts, so sync cannot dedupe highlights.
- Under pagination, the selection is translated to whole-document offsets and pagination is turned off (`:35-70`). "Clear" stores `[]` instead of deleting the key (`:104-114`).
- Render: an entry is skipped if `start >= end` or `end > characterCount` (`:134-138`).

#### 2.5 `reading_stats`: `{path: {seconds, words_read, words_total, pct, sessions, last_ts}}`

- `ReadingStats.tick(speaking, path, word_idx, total_words)` counts time only while speech plays. Each session increments `sessions`. `words_read` is the maximum reached. `pct = int(100*words_read/total)`.
- Stats flush every **5 s** while speaking and on stop, which **rewrites settings.json** every 5 s (`stats.py:41-129`).
- `seconds` is rounded to 1 decimal. **Cap:** more than 500 entries evicts the 100 oldest by `last_ts`.

#### 2.6 `library`: `{path: {title (≤200 chars), format, added, last_opened}}`

- Written on every non-welcome, non-error document open and on Save-As adoption (`stats.py:132-149`). **Cap:** more than 500 entries evicts the 100 with the oldest `last_opened`.
- The GUI Library view merges scanned library-folder files (sidecar `pct` preferred) with `library` entries outside any folder, labeled `"recent"` (`gui/mixin_doctools.py:404-443`).
- Obsidian import also writes library entries (§4.8).

#### 2.7 Parse cache: `<cfg>/cache/<md5(path)[:16]>_<fp8>_v1.json`

- Payload: `{version:1, path, mtime, settings_fingerprint, data}`. The fingerprint is `md5("tts_skip_code|table_reading_mode|footnote_mode|pdf_reading_order|prefer_pandoc")[:8]` (`stats.py:10-21`).
- Skipped for URLs and for files under 1 KB. An entry is invalid if `|mtime - cached| > 1e-3`, in which case the file is deleted.
- Plain `write_text`, not atomic. No size cap or eviction (`cache.py`).

#### 2.8 Navigation history

In-memory only; it is never persisted. It is a list of TTS offsets with a cursor, where `-1` means "live" (`gui/mixin_bookmarks_qt.py:26-33,195-248`). Branching discards the forward entries. The list is trimmed to `nav_history_size`. Status messages: `Navigation history is empty.`, `No earlier history.`, `No forward history.`, `History: at present position.`, and `History: position {n}/{total}`.

### 3. Sync / sidecar merge (`star/sync.py`, `star/library.py`)

#### 3.1 Sidecar file

- **Location:** `<libraryFolder>/.star/progress.json` (`library.py:135-136`). The `.star` directory is in `_SKIP_DIRS`, so it is never scanned (`library.py:20-24`).
- **Format:** a JSON object written with `indent=2, ensure_ascii=False`:
  ```json
  {
    "sub/book.epub": {"offset": 1200, "pct": 42, "ts": "2026-06-27T10:00:00"},
    "_meta": {"sub/book.epub": {"seconds": 1234, "pct": 55, "last_ts": "...", "annotations": 3}}
  }
  ```
- Document keys are POSIX relative paths (`folder_for` → `rel.as_posix()`, picking the **deepest** folder by resolved-path string length, `library.py:271-289`).
- `_meta` is reserved (`library.py:145`, `sync.py:43`; a test pins them equal). Each `_meta` entry holds `seconds`, `pct`, and `last_ts` (the portable stats subset, `library.py:297`), plus `annotations` (the count) when that count is greater than 0. The entry is omitted when empty (`library.py:300-318`). `words_read` is deliberately excluded.
- `load_sidecar` hides `_meta` (`library.py:188-195`).
- **Annotations and highlights are not written to the sidecar today**; only their count is. The by-id merge (§3.3) exists for future sidecars.
- **Write path** (`record_progress`, `library.py:321-369`):
  1. Everything runs under a process-wide lock.
  2. `data = pending or disk`, then `data[rel] = entry`, then `_meta[rel]` is updated. The result is stored in `_pending`.
  3. If the last flush for this sidecar was less than **0.5 s** ago, return True without writing (debounce).
  4. Otherwise `to_write = merge_progress(data, disk, policy, prefer="local")`.
  5. **`to_write[rel] = entry` is re-asserted** (along with its `_meta`), then the file is written atomically (temp file in the same dir, fsync, `os.replace`; failures return False, `library.py:229-263`). On success, `_last_write` is updated and `_pending` is cleared.
- `flush_pending(folder, settings=None)` merges pending data with disk, using the configured policy or `newest` when no settings are passed, then writes (`library.py:372-396`). **Nothing in the app calls it** (§7).
- Reads: `progress_for`, `metadata_for`, `metadata_by_folder`, and `sidecars_by_folder` all prefer the pending in-memory value (`library.py:175-185,399-437`).

#### 3.2 `merge_progress(local, remote, policy="newest", prefer="remote") -> (merged, [Conflict])` (`sync.py:271-319`)

- An unknown `policy` becomes `"newest"`. Non-dict top-level input (None, list, str, number) is treated as `{}` (`_as_dict`).
- **Key order:** the local keys in their original order, then remote-only keys in remote order. Port with an order-preserving map such as `IndexMap`.
- Per key, the first matching route applies:
  1. `key == "_meta"` → `_merge_meta` (§3.4).
  2. `key in {"annotations","highlights","user_highlights"}` **or** `_is_annotation_list(l, r)` → `merge_annotations` (§3.3). `_is_annotation_list` returns False if either side is a dict, and True if either side is a list (`sync.py:322-339`). A known annotation key with a dict value still routes here and the dict is coerced to `[]`.
  3. Otherwise → `_merge_entry` (§3.5).
- `Conflict` has the fields `path`, `field` (None for a whole entry, the id for an annotation, the rel for `_meta`), `local`, `remote`, and `resolution`. `resolution` is one of `"local"`, `"remote"`, `"unresolved"`, and defaults to `"unresolved"` (`sync.py:53-69`). `"merged"` is documented but never produced.

**Helpers (exact semantics):**

- `_ts_key(e)`: returns `""` if `e` is not a dict. Otherwise uses `e["ts"]`, or `e["last_ts"]` if `ts` is missing or None, converted with `str()`. The result is compared as a plain **string** (lexicographic). A missing timestamp sorts earliest (`sync.py:79-94`).
- `_progress_value(e)`: returns the first of `offset` or `pct` that is an int or float **and not a bool**, as a float. Otherwise returns -1.0 (`sync.py:97-110`).
- `_newest(l, r, prefer)`: if `rt > lt`, remote wins. If `lt > rt`, local wins. On a tie, `prefer=="local"` picks local and anything else picks remote (`sync.py:160-179`).
- Equality is Python `==` deep equality. Note that `1 == 1.0` is True in Python. `serde_json::Value` treats integer 1 and float 1.0 as different numbers, so normalize numbers before comparing if you need parity.

#### 3.3 `merge_annotations(key, local, remote, conflicts=None, prefer="remote")` (`sync.py:191-246`)

- A non-list side is treated as `[]`. The id is `str(a["id"])` when `a` is a dict and the id is truthy. `""` and `0` count as having no id, and `1` and `"1"` collide.
- Algorithm:
  1. Build `remote_by_id`, where the **last** duplicate on the remote side wins, and `remote_idless`, preserving order.
  2. Walk local in order:
     - An entry without an id is appended.
     - Otherwise add the id to `seen`. If the remote has no such id, or the remote entry is `==` the local one, append the local entry.
     - Otherwise append `_newest(local, remote, prefer)`'s winner and record `Conflict(key, id, local, remote, res)`.
     - Local duplicate ids are each appended.
  3. Walk the remote list in order and append entries whose id is not in `seen`. This emits the **first** remote occurrence of an id, then marks it seen.
  4. Append `remote_idless`.

#### 3.4 `_merge_meta` (`sync.py:249-268`)

Start from `dict(local_meta)`. For each remote rel:
- If the local side is missing, take the remote entry.
- If the two are equal, keep local.
- Otherwise use `_newest` (`last_ts` is used when `ts` is absent) and record `Conflict("_meta", rel, ...)`.

The policy is ignored here; `_meta` always uses newest-wins with `prefer`.

#### 3.5 `_merge_entry(key, l, r, policy, conflicts, prefer)` (`sync.py:113-157`)

- If `r is None`, return `l`. If `l is None`, return `r`. Neither case records a conflict.
- If `l == r`, return `l`.
- `highest_progress`: the larger `_progress_value` wins. On equal values, fall back to `_newest`. Always records a Conflict with the winning side.
- `manual`: return **local** and record a Conflict with resolution `"unresolved"`.
- Otherwise (`newest`): use `_newest` and record a Conflict with the resolution.
- A corrupt (non-dict) side is **not** skipped here. It simply has an empty `ts` and progress -1, so it loses unless ties or the `prefer` direction favor it.

### 4. Authoring (GUI edit mode, `star/gui/mixin_authoring.py` and `gui/mixin_navigation/_editing.py`)

#### 4.1 Edit-mode model

- **Enter** (Ctrl+E): stop TTS. Make the editor read-write with a 2 px cursor. `setPlainText(doc.markdown)` puts the **converted Markdown** (not the raw source) in the editor. All char and block formats are reset. `modified=False`, `edit_mode=True`, `dirty=False`. The contents-changed listener is connected, the format toolbar is shown, autosave starts, and the spell highlighter is attached. If `qt_edit_preview` is on, the preview is shown and rendered and the split is set to 50/50 (`_editing.py:157-207`).
- Status on enter (fixed text): `✏  EDIT MODE — Markdown source + live preview  ·  Ctrl+S: save (keep editing)  ·  Ctrl+E: finish` when the preview is on. Otherwise `✏  EDIT MODE — Markdown source  ·  Ctrl+S: save (keep editing)  ·  Ctrl+E: finish  ·  Ctrl+Shift+Z: live preview`. With no doc: `No document to edit`.
- **First change** sets dirty and shows `✏  EDIT MODE  ·  {title}  [modified — Ctrl+S to save]`. The preview re-renders 300 ms after the last keystroke (`_editing.py:209-220`).
- **Ctrl+E while editing** (`_qt_finish_editing`, `:63-78`): if dirty, a QMessageBox titled "Finish Editing" asks "Save changes before leaving edit mode?" with Save / Discard / Cancel.
  - Cancel keeps editing.
  - Save calls `_qt_persist_edits`. On failure or a cancelled Save-As, the user stays in edit mode.
  - Then `_qt_exit_edit_mode`: tear down (disconnect, stop and clear autosave, hide toolbar and preview, read-only), re-render the HTML, rebuild the TOC, annotations, and highlights, and rebuild the word maps (on a background thread) **only if a save happened** (`_qt_maps_stale`). Status: `Read mode` (`:222-264`).
- **Opening another document mid-edit** runs the same Save/Discard/Cancel prompt (`_qt_confirm_leave_edit_for_replace`, `:115-131`). As a safety net, `_on_doc_loaded` also tears edit mode down (tested).
- **Ctrl+Shift+Z** toggles `qt_edit_preview` (persisted). Turning it on outside edit mode enters edit mode. Status: `Live HTML preview: ON` / `OFF` (`:332-356`).

#### 4.2 Save rules (`_qt_persist_edits`, `_editing.py:360-446`; `_qt_save`, `:539-573`)

- **Read mode Ctrl+S** runs Export as Markdown instead (`:553-556`).
- **In place** when `doc.path` has a suffix (case-insensitive) in `{.md,.markdown,.txt,.rst,.org,.adoc,.asc,.asciidoc}`. The file is written with `Path.write_text(new_md, "utf-8")`, which is not atomic, adds no BOM, and translates newlines by platform (§7).
- **Save-As** in every other case: no path (new doc), a binary or converted format, or a URL. The dialog is titled "Save As Markdown", its default is `<orig parent>/<orig stem>.md` (or `document.md` for a new doc), and its filter is `Markdown (*.md *.markdown)`. An empty choice returns False. The extension is **not** forced to `.md`.
- After any successful write:
  - `doc.markdown` is set to the new text.
  - `doc.plain_text` is set to `_strip_markdown_for_tts(new_md, skip_code, table_mode)`.
  - dirty is cleared, the autosave snapshot is deleted, and `_qt_maps_stale=True`.
- After a Save-As, the document **adopts the path** (`doc.path=dest`, `doc.title=stem`) and is recorded in the library, so the next Ctrl+S writes in place (tested).
- A write error shows `Save error: {exc}` through `_status_error` (persistent status message, announced, logged to history) and returns False.
- `_qt_save` then stays in edit mode, re-renders the preview if visible, shows `Saved → {path}  ·  still editing (Ctrl+E to finish)`, announces `Saved. Still editing.`, and focuses the editor.

#### 4.3 Markdown formatting commands

All are no-ops outside edit mode and show `Turn on Edit Mode (Ctrl+E) to format text` in the status bar only, with no announcement (`mixin_authoring.py:62-69`). After each command the editor is focused and the preview is re-rendered immediately if visible, cancelling the debounce (`:71-87`). Bindings come from the Format menu (`mixin_chrome.py:627-665`), the toolbar (`:185-217`), and the editor context menu (`mixin_history.py:78-98`, which has no table or image items). **No command toggles** (applying it twice doubles the markup), and **no command inspects existing markup**.

| Command | Shortcut | Call | Transformation |
|---|---|---|---|
| Bold | Ctrl+B | `_qt_md_wrap("**","**","bold text")` | wrap |
| Italic | Ctrl+I | `_qt_md_wrap("*","*","italic text")` | wrap |
| Underline | Ctrl+U | `_qt_md_wrap("<u>","</u>","underlined text")` | wrap (inline HTML) |
| Inline Code | none | `_qt_md_wrap("`","`","code")` | wrap |
| Heading | none | `_qt_md_line_prefix("# ")` | line prefix, **level 1 only** (no H2-H6, no cycling) |
| Bullet List | none | `_qt_md_line_prefix("- ")` | line prefix |
| Numbered List | none | `_qt_md_line_prefix("", numbered=True)` | `1. `, `2. `, ... per line |
| Quote / Block Quote | none | `_qt_md_line_prefix("> ")` | line prefix |
| Link / Insert Link | Ctrl+K | `_qt_md_link()` | see below |
| Horizontal Rule | none | `_qt_md_insert_rule()` | see below |
| Insert Table… | none | `_qt_md_insert_table()` | see below |
| Add Table Row | none (menu only) | `_qt_md_table_add_row()` | see below |
| Insert Image… | none | `_qt_md_insert_image()` | see below |
| Undo / Redo | none (native Ctrl+Z/Y in the editor) | `_qt_undo` / `_qt_redo` | Outside edit mode: `Undo works while editing (Ctrl+E)` / `Redo works while editing (Ctrl+E)`. Otherwise status and announcement `Undo` / `Redo` (`mixin_history.py:54-68`) |

Other shortcuts in this area: Ctrl+M adds a bookmark, Ctrl+N creates a new document, Ctrl+S saves, Ctrl+E toggles edit mode, and Ctrl+Shift+Z toggles the preview.

**`_qt_md_wrap(before, after, placeholder)`** (`mixin_authoring.py:89-107`)
- With a selection, the selection is replaced by `before + sel + after`, where `sel` comes from `QTextCursor.selectedText()`. `selectedText()` returns line breaks as U+2029, and Qt's `insertText` turns U+2029 back into a block break, so a **multi-line selection is wrapped once as a whole**: `**a⏎b**`. It is not wrapped per line, and no whitespace trimming happens (derived). Afterwards the cursor sits after `after` with no selection.
- With no selection, `before + placeholder + after` is inserted, and **the placeholder is selected** (anchor at the placeholder start, cursor at the placeholder end).
- The command is one `insertText`, so it is one undo step.

**`_qt_md_line_prefix(prefix, numbered=False)`** (`:109-128`)
- The blocks run from `findBlock(selectionStart)` to `findBlock(selectionEnd)`. With no selection, only the current line is affected.
- The prefix is inserted at the **start of each block**, including empty lines. When `numbered` is set, the i-th block gets `f"{i+1}. "` and `prefix` is ignored. Existing prefixes and numbers are not detected.
- A selection that ends at column 0 of the next line also prefixes that line (derived).
- The whole operation is wrapped in `beginEditBlock` / `endEditBlock`, so it is **one undo step** (the docstring says so; untested).
- The selection is not restored explicitly. Qt shifts existing cursors past the inserted text (derived).

**`_qt_md_link()`** (`:130-139`)
- Inserts `[{selectedText or "text"}](https://)`, replacing the selection.
- The cursor ends after `)`, and **nothing is selected**, even the `text` placeholder. This is inconsistent with the wrap commands.

**`_qt_md_insert_rule()`** (`:141-149`)
- Inserts `"\n---\n"` at the cursor, replacing any selection. It does not check whether the cursor is at a line start.
- Mid-line, the line is split. Right after a text line, `text⏎---` renders as a **setext H2**, not a rule (§7).

**`_md_table_skeleton(rows, cols)`** (`:153-164`)
- Both arguments are clamped to at least 1.
- Header: `| Column 1 | Column 2 | ... |`. Separator: `| --- | --- |`.
- Each body row is `"| " + " | ".join(" "×cols) + " |"`. For 3 columns that is `|   |   |   |`, with three spaces per cell.
- The output ends with `\n`.

**`_qt_md_insert_table()`** (`:166-192`)
- Asks for columns first (default 2, range 1-20), then rows excluding the header (default 2, range 1-100). Cancelling either prompt aborts.
- Inserts `("" if cursor.atBlockStart() else "\n") + "\n" + skeleton + "\n"`.
- The docstring claims the first body cell ends up selected; **the code does not do this**.
- Announces `Inserted a {r}×{c} table`.

**`_qt_md_table_add_row()`** (`:194-217`)
- Requires the current line to contain `|` and its stripped form to start with `|`. Otherwise shows `Put the cursor inside a table row to add a row`.
- `cols = line.strip().strip("|").count("|") + 1`. Escaped or code pipes are miscounted.
- Inserts `"\n" + new_row` at the end of the **current** line. On the header line this lands between the header and the separator, which breaks the table (§7).

**`_qt_md_insert_image()`** (`:221-255`)
- File filter: `Images (*.png *.jpg *.jpeg *.gif *.webp *.bmp *.svg);;All Files (*)`.
- If the doc has a path, the reference is `relpath(src, doc_dir)` with `/` separators, unless it starts with `../../` (two or more levels up), in which case the absolute path is kept. On a different Windows drive the absolute path is used.
- Inserts `![{stem}]({ref})`. The docstring promises a prompt offering the relative path and a selected alt text; **the code does neither**.
- Announces `Inserted image {filename}`.

**New document** (`:23-58`)
- Runs the Save/Discard/Cancel prompt first. Then creates `Document(path="", title="Untitled", markdown="", plain_text="", format="markdown")`, **persists `qt_edit_preview=True`**, applies the doc (bumping the load generation so a stale welcome load is dropped), enters edit mode, and sets a 50/50 split.
- Status: `New document — start typing or dictate`. Announcement: `New document ready for editing`.

#### 4.4 Find & Replace (edit mode; `gui/mixin_find.py`)

- **Matching** (`:481-500`): substring match, case-insensitive by default (`.lower()` on both sides), with **overlapping** matches (the scan advances 1 char past each hit). Offsets are Python code-point indices used as QTextCursor positions, which are UTF-16 (§7).
- `_find_run` picks the first match at or after the cursor `position()`. After a reveal, `position()` is the end of the selected match, so running the search again moves on to the next match (derived).
- **Replace one** (`:231-259`): replaces the current match range, re-runs the search, and shows `Replaced 1 match` in the status bar (not announced). Outside edit mode: `Turn on Edit Mode (Ctrl+E) to replace text`. With no active match it does nothing.
- **Replace all** (`:261-291`): works back to front inside one edit block, so it is **one undo step** (tested). It shows and announces `Replaced {n} matches`. With no matches: `No matches`.
- Overlapping matches plus back-to-front replacement **corrupt the text** for self-overlapping queries (§7).

#### 4.5 TUI authoring (`star/tui/mixin_editing.py`)

- **Editor command:** `$VISUAL`, then `$EDITOR` (shlex-split; POSIX rules except on Windows), then `notepad` on Windows, then `nano` or `vi`. With none found: `No editor found — set $EDITOR (or $VISUAL) and try again.` Curses is suspended while the editor runs (`:37-84`).
- **Ctrl+E / M-x edit:** a text-extension file that exists on disk is edited in place and reloaded. Anything else gets a temp draft `<stem>-XXXX.md` holding `doc.markdown`, read back as `utf-8-sig`. Unchanged content shows `No changes made`. Otherwise a minibuffer prompts `Save edited Markdown as: ` with default `<path>.md`, or `cwd/<stem>.md` for URLs. The suffix is forced to `.md` unless it is already `.md` or `.markdown`. On failure the draft is kept and its path reported (`:88-214`).
- **Ctrl+N / new-document:** prompts `New document path: ` (default `cwd/untitled.md`). A non-text suffix is replaced with `.md`. If the file exists: `{p} already exists — open it and use edit instead`. Otherwise it writes `# {stem}\n\n`, opens the editor, then loads the file (`:115-154`).

#### 4.8 Obsidian (wave-2 notes, `star/obsidian.py`)

**Import**, `import_vault(settings, dir, link_relation=None, mode="graph"|"library")`:
- Recursively reads `*.md`, skipping `.obsidian` and `.trash`.
- Front matter is parsed with YAML if available, otherwise with a minimal parser.
- Every note becomes a `library[str(path)]` entry (`title` from front matter, else the stem).
- In graph mode, each note gets one node annotation: `char_pos 0`, `word_idx 0`, tag `obsidian-note`, `anchor=title`, `note` = the first content line with link syntax stripped (≤200 chars), and `id = front matter star_id`, else a uuid8.
- `relations` are rebuilt on each import:
  - A typed Dataview field `rel:: [[T]]` becomes a relation when `rel` normalizes (uppercase, spaces and hyphens to `_`) to a known type.
  - An untyped `[[T]]` becomes `link_relation`, then `vault.default_link_relation`, then `SEE_ALSO`.
  - `![[embeds]]` are ignored.
  - Targets resolve by stem, title, or aliases (case-insensitive, first registration wins).
  - Duplicate (type, target) pairs are deduped. Unresolved links are counted.
- Returns `{vault, mode, notes, relations, unresolved}` (`obsidian.py:142-252`).

**Export**:
- One file per graph node, named after the sanitized anchor or note (`<>:"/\|?*` and control characters become spaces, max 120 chars), with ` 2`, ` 3`, ... appended to break case-insensitive clashes.
- File content:
  - Front matter with `star_id`, `title`, `source`, and `tags: [..]`. Values are **not YAML-quoted** (§7).
  - The note body.
  - A `## Links` section with one `- REL:: [[name]]` line per relation.
- (`obsidian.py:263-324`)

| Tick writes only if | not closing, `autosave_recovery` on, in edit mode, and dirty | `:151-173` |
| File | `<cfg>/recovery/<key>.json`. The key is `doc-` + `sha1(os.path.abspath(path))[:16]` for a saved doc, or `untitled-` + a 12-hex per-window id | `:39-53,139-142` |
| Format | Compact JSON (`ensure_ascii=False`): `{"path","title","markdown","ts":"YYYY-mm-ddTHH:MM:SS","app_version"}`. Written to `<key>.tmp` and then `replace`d (no fsync). `title` is `doc.title` (tr("Untitled") only when there is no doc) | `:56-65,166-173` |

| **Not** cleared | Window close while dirty. There is also **no close prompt and no final tick**, so up to 20 s of typing is lost (§7) | `main_window.py:1181-1239` |

#### 5.2 Recovery flow

1. At startup, `QTimer.singleShot(0, _autosave_check_on_startup)` (`main_window.py:719`). Nothing happens if the window is closing or `autosave_recovery` is off.
2. `_scan_snapshots(<cfg>/recovery)` reads `*.json` in sorted filename order and skips unreadable files, non-dicts, and dicts without `markdown`. When `path` is set and that file's current text `== markdown`, the snapshot is stale: the file is **deleted** and skipped. A missing or unreadable original is still offered. A `_file` key is added to each snapshot (`:68-96`).
3. For each snapshot, one modal prompt (skipped if `_modal_ok()` is false). Title `Recover unsaved work?`. Text: `star closed with unsaved changes to “{title}” ({when}).\n\nRecover them now?`. Buttons Yes / No (`:192-209`).
4. **Yes** runs `_autosave_recover`:
   - The current edit is resolved with the Save/Discard/Cancel prompt. On Cancel, return and **keep the snapshot**.
   - Apply `Document(path=<snapshot path>, title=<title or "Recovered document">, markdown=md, plain_text="", format="markdown")`, then enter edit mode, set **dirty=True**, and focus the editor.
   - Delete the snapshot file.
   - Status `Recovered unsaved work — remember to save`. Announcement `Recovered unsaved work. Remember to save.` (`:221-246`)
5. **No** deletes the snapshot file (`:213-219`).

### 6. Announcements

#### 6.1 Mechanism

**GUI.** `star/gui/a11y.py:72-106`: `announce(widget, text)` sends `QAccessibleEvent(widget, QAccessible.Event.Announcement)` with `setValue(text)` when available.
- Returns False and does nothing when the text is empty, the widget is None, Qt has no Announcement event, or `QAccessible.isActive()` is false (e.g. offscreen). It never raises.
- The resolver result is cached (`:37-69`).
- By convention each call is paired with `statusBar().showMessage(text)`. **The status bar itself is not spoken.** Only explicit `announce` calls reach screen readers.
- `_status_error(msg)` shows a persistent message, announces it, and logs it to the command history (`gui/mixin_display.py:24-37`).

**TUI.** There is no speech for status. `notify(msg, dur=4.0, error=False)` shows a toast on the status row. Errors last at least 8 s, use the error attribute, and are logged (`tui/app.py:215-224`, `tui/mixin_draw.py:313-322`). Accessibility comes from **terminal cursor placement**: outside input modes the hardware cursor is parked on the SC line, else the caret word (row and column), else the spoken line, else the first visible line (`tui/mixin_draw.py:30-70`). The title bar shows `▶ Speaking`, `■ Stopped`, `▶ SC+Speaking`, or `● SC CURSOR`, followed by `{rate} wpm` and the backend (`:72-85`).

**Speech Cursor "blank".** In both UIs, reading an empty line or block **speaks** the literal word `"blank"` through the SC reader or the backend. The GUI also shows `SC  —  line {n}: (blank)` (`tui/mixin_speechcursor.py:87-94`, `gui/mixin_navigation/_speechcursor.py:325-333`).

**Verbosity.** No verbosity or announcement-level setting exists; a search for `verbos`, `announce_`, and `speak_status` finds nothing relevant.

### 7. Known bugs and quirks worth fixing in the port

#### Settings

1. **The whole settings.json is rewritten on every `set()`** (`settings.py:481-483`). Frequent writers:
   - reading-stats flush every 5 s while speaking (`stats.py:101-103,129`)
   - every reading-position save and stop
   - every bookmark, note, or highlight change
   - `ReadingStats`, `TTSManager.set_rate` (`tts/manager/_playback.py:374-380`), and similar callers

   Large `annotations` and `reading_stats` maps make each write costly. Port with a dirty flag and debounced saves, or split per-document state out of the preferences file.
2. **Every default is persisted**, so changing a default in a new release never reaches existing users. This is why `_migrate` needs special cases (`settings.py:405-418,450`).
3. **Shallow copy of `DEFAULTS`** (`settings.py:361`). Keys that are absent from the file share the module-level list and dict objects. In-place mutation then corrupts `DEFAULTS` for every later `Settings()` in the process. Examples: TUI `recent_files.insert` (`tui/mixin_document.py:78-80`), `_data.setdefault("user_highlights", {})` (`gui/mixin_highlights.py:72`), and Obsidian's `settings["annotations"]` (`obsidian.py:160,192`).
4. **Load crashes on some bad files.** A top-level JSON array or scalar raises `AttributeError` at `raw.items()`, and non-UTF-8 bytes raise `UnicodeDecodeError`. Neither is caught (`settings.py:367-384`). Value types are never validated, so for example `"tts_rate": "fast"` later fails at `int()`.
5. **Unknown keys are silently dropped on load** (`settings.py:373`). As a result `publish_options` never persists, and a hand-set `summary_sentences` is ignored (§1.2). `whisper_chunk_seconds` is never read.
6. **Nested dict merge.** Keys removed from `speed_presets`, `graph`, `vault`, or `video` come back after a restart (`settings.py:376-379`).
7. **Inconsistent ranges.** Rate is clamped to 50-600 by hotkeys but offered as 50-400 in Preferences (`gui/mixin_display.py:42`, `preferences.py:558`).
8. **Preferences rewrites some zero values.** `float(settings.get("tts_volume") or 1.0)` turns a saved volume of 0 into 100 %, and OK then writes 1.0 (`preferences.py:566-567`). `qt_ruler_opacity` 0 becomes 22 in the same way (`:345`).
9. **Preferences writes `tts_backend="silent"`** for "none" (`preferences.py:978`), while the documented value is `none`.
10. **CLI flags persist.** `--rate`, `--theme`, and `--backend` are saved permanently (`app.py:357-365`).
11. **API key storage.** `elevenlabs_api_key` is stored in plain text in settings.json.

#### Normalization / export

12. **`footnote_mode: "inline"` is a no-op.** Both loaders skip `_process_footnotes` for `inline` (`documents/dispatch.py:300-302`, `documents/handlers.py:28-30`), so the `(footnote: …)` inline expansion (`documents/misc.py:84-90`) never runs. In the GUI, `_footnotes_to_anchors` renders references as `[n]` superscripts with a Footnotes list at the end (`gui/mixin_document.py:907-964`). Speech therefore reads the notes at the end rather than at the reference, contrary to the docs (`configuration.md:132`).
13. **`video.subtitles: "burn"` behaves like `none`.** Only `soft` attaches the SRT (`video.py:59,130`). The docs also omit `burn` (`configuration.md:122`).

#### Per-document state

14. **Inconsistent document keys.** `user_highlights` uses `path or "__no_path__"`, while bookmarks and annotations use `path or title`, so every untitled or in-memory document shares one highlight bucket.
15. **Unnormalized paths.** Keys are raw paths, never resolved or case-folded, so the same file opened through different path spellings gets separate state (§2).
16. **TUI notes sort first in the GUI.** TUI-created annotations store `char_pos 0` (`tui/mixin_annotations.py:75`), and the GUI sorts and shows percentages by `char_pos`, so those notes sort to the top and read 0 %.
17. **Highlight offsets depend on rendering.** `user_highlights` are rendered-editor char offsets, so they depend on rendering (derived: display-only transforms such as syllable splitting, bionic reading, or theme HTML changes can shift them). They have no id or ts, so they cannot sync.
18. **Annotations get no id on creation** (`gui/mixin_annotations.py:150-159`). Any future sidecar annotation sync would treat them as id-less and duplicate them on every merge.
19. **Local timestamps without a zone** drive the "newest" comparisons across machines in different time zones. Arbitrary strings such as `"t"` or `"legacy"` compare lexicographically. Use UTC RFC 3339.
20. **Welcome page.** The GUI saves a reading position for the welcome page while the TUI skips it (`tui/mixin_navigation.py:137` vs `_position.py:20-24`).
21. **Recents.** `recent_files` and `last_path` are maintained only by the TUI, and existing entries are not moved to the front.

#### Sync

22. **`flush_pending` is never called by the app.** Only tests call it. A position recorded within 0.5 s of the previous sidecar write, for example stop then quit, stays in memory and is lost at exit (`library.py:350-354,372`).
23. **The written document's entry is forced to local.** `record_progress` re-asserts the local entry after the merge (`library.py:358-363`), so `highest_progress` and `manual` never protect the document being written. A glance at 5 % on device B overwrites 80 % from device A.
24. **Conflicts are discarded.** `_reconcile_before_write` throws away the conflict list (`library.py:225-226`) and nothing surfaces conflicts, so `manual` just means "keep local silently".
25. **Resume ignores the policy.** It picks the sidecar entry over the local one by string timestamp alone (`_position.py:67-70`).
26. **The TUI never reads or writes sidecars.**
27. **Merge quirks** (§3.3):
    - Duplicate remote ids: the last duplicate is used for comparison, but the first is emitted for remote-only ids.
    - A dict under a known annotation key is coerced to `[]`.
    - A falsy id counts as id-less.
    - Numbers and strings collide once converted to `str`.

#### Authoring

28. **In-place save can overwrite a non-Markdown source with Markdown.** Edit mode loads `doc.markdown`, the *converted* Markdown (`_editing.py:166`), but saves in place for `.rst`, `.org`, `.adoc`, `.asc`, `.asciidoc`, and `.txt` (`:376-393`). Those loaders convert to Markdown (e.g. `documents/text_loaders.py:97-115`), so saving an `.rst` file overwrites its reStructuredText with Markdown.
29. **Unsafe save writes.**
    - Saves use non-atomic `write_text` (`_editing.py:389,410`). The original encoding, BOM, and line endings are not preserved.
    - On Windows, text mode writes CRLF (derived from Python's newline translation).
    - Save-As does not force a `.md` extension (`:401-410`).
30. **Commands never toggle.** No command detects existing markup, so bolding twice gives `****x****` and headings stack as `# # Title`. Heading is H1 only. Multi-line wrap wraps across paragraphs once (§4.3).
31. **Link placeholder is not selected**, unlike the wrap commands (`mixin_authoring.py:130-139`).
32. **Horizontal rule after text renders as a heading.** Inserting after a text line creates a setext H2 (`"above\n---"`); a blank line is needed before `---` (`:141-149`).
33. **Docstrings promise behavior the code doesn't implement:**
    - Insert Table does not select the first body cell (`:166-170`).
    - Insert Image neither prompts for a relative path nor selects the alt text (`:221-227`).
    - Add Row on the header line breaks the table.
34. **File ▸ New persists `qt_edit_preview=True`** as a side effect (`mixin_authoring.py:45`).
35. **Find/Replace offset errors.**
    - Overlapping matches plus back-to-front Replace All garble self-overlapping queries (e.g. `aa` in `aaa`) (`mixin_find.py:481-500,283-286`).
    - Python code-point offsets are used as QTextCursor positions, which count UTF-16 units, so offsets drift after any non-BMP character.
    - `.lower()` can change string length, e.g. `İ`.
    - Re-running a search skips the current match.
36. **Possible Ctrl+Shift+Z conflict (unverified).** Ctrl+Shift+Z is the preview toggle, but it is Redo on Linux and macOS; confirm who wins in the port.
37. **Missing announcements.** Rate changes, caret-browsing and Speech Cursor toggles, edit-mode enter/exit, `Replaced 1 match`, and resume position are status-bar only (§6.3). The TUI pause gives no feedback at all (`tui/mixin_playback.py:133-143`).

#### Autosave

38. **Closing the window with unsaved edits** gives no prompt and no final snapshot (`main_window.py:1181-1239`). Up to 20 s of work is lost, and the next launch treats a normal quit as a crash.
39. **Multiple instances.** A second instance offers to "recover" the snapshot that a still-running first instance owns; there is no lock or PID check (`mixin_autosave.py:176-190`).
40. **Snapshot writes use a fixed `<key>.tmp` name and no fsync** (`:56-65`).
41. **Declining the save prompt during recovery keeps the snapshot** (derived). It is offered again on the next launch.

#### Obsidian export

42. **Front matter values are not YAML-quoted** (`obsidian.py:297-303`). A title containing `: `, `#`, or leading `[` produces invalid or mis-typed YAML.

#### Docs drift

43. **Stale comments and docstrings:**
    - `test_sync.py:492` says `sync_conflict_policy` is absent from DEFAULTS, but it is at `settings.py:94`.
    - The `_qt_check_spelling` docstring says F7, but F7 is Caret Browsing (`_editing.py:266-267`, `mixin_chrome.py:872-875`).
    - `Conflict.resolution` documents `"merged"`, but it is never produced.
